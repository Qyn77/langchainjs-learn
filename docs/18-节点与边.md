## 📦 节点（Node）深入

### 节点的标准形态

节点就是一个函数：

```javascript
// 同步节点
const nodeA = (state) => {
  return { foo: state.foo + 1 };  // 返回状态更新
};

// 异步节点（调用 LLM、请求 API 都是异步的）
const nodeB = async (state) => {
  const response = await model.invoke(state.messages);
  return { messages: [response] };
};

// 注册到图
const graph = new StateGraph(StateAnnotation)
  .addNode("nodeA", nodeA)
  .addNode("nodeB", nodeB)
  ...
```

### 节点的第二个参数：config

节点还能拿到第二个参数 `config`，包含运行时信息：

```javascript
const myNode = async (state, config) => {
  // config.configurable：调用图时传入的可配置项
  const userId = config.configurable?.userId;

  // config.writer：向流式输出发送自定义数据（第 25 章详解）
  config.writer?.({ progress: "处理中..." });

  return { /* 更新 */ };
};
```

### 节点返回 Command：一步控制"更新 + 去向"

默认情况下，节点只返回状态更新，"下一步去哪"由边决定。但节点也可以用 `Command` 同时指定两件事：

```javascript
import { Command } from "@langchain/langgraph";

const routerNode = (state) => {
  if (state.score >= 60) {
    // 更新状态 + 跳转到指定节点
    return new Command({
      update: { result: "及格" },
      goto: "celebrate",           // 下一步去 celebrate 节点（或 END）
    });
  }
  return new Command({
    update: { result: "不及格" },
    goto: "remedial",
  });
};
```

> 💡 **说明：** `Command` 的 `goto` 和条件边（第 19 章）功能有重叠。经验法则：**分支逻辑比较简单时用 `Command`（少定义一个路由函数），分支复杂或需要复用路由逻辑时用条件边**。

## 🔗 边（Edge）深入

### 普通边：固定路线

```javascript
.addEdge("nodeA", "nodeB")   // A 执行完必然轮到 B
.addEdge(START, "nodeA")     // 图的入口
.addEdge("nodeB", END)       // 图的出口
```

### 扇出（Fan-out）：一个节点后并行跑多个

**同一个源节点引出多条边，目标节点就会并行执行**（在同一个超级步里）：

```javascript
.addEdge("start_node", "nodeA")
.addEdge("start_node", "nodeB")  // nodeA 和 nodeB 并行执行
```

### 扇入（Fan-in）：多路结果汇聚

多个节点都指向同一个目标节点，目标节点会**等所有上游都完成**后才执行：

```javascript
.addEdge("nodeA", "join")
.addEdge("nodeB", "join")  // join 会等 nodeA 和 nodeB 都执行完
```

> ⚠️ **注意：** 并行的节点如果写同一个状态字段，该字段必须有 reducer（第 17 章讲过的规则）。

## 💡 实战 1：三步写作流水线

一个顺序工作流：生成大纲 → 写正文 → 润色。

创建 `writing-pipeline.js`：

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

// 定义状态：每步的产出都是"覆盖"语义
const StateAnnotation = Annotation.Root({
  topic: Annotation,      // 主题
  outline: Annotation,    // 大纲
  draft: Annotation,      // 初稿
  final: Annotation,      // 终稿
});

// 节点 1：生成大纲
async function generateOutline(state) {
  const res = await model.invoke(`为文章「${state.topic}」列一个 3 点大纲，只返回大纲。`);
  return { outline: res.content };
}

// 节点 2：写正文
async function writeDraft(state) {
  const res = await model.invoke(`根据以下大纲写一段 150 字的正文：\n${state.outline}`);
  return { draft: res.content };
}

// 节点 3：润色
async function polish(state) {
  const res = await model.invoke(`润色以下文字，使其更有感染力：\n${state.draft}`);
  return { final: res.content };
}

// 构建图：纯线性流水线
const graph = new StateGraph(StateAnnotation)
  .addNode("generateOutline", generateOutline)
  .addNode("writeDraft", writeDraft)
  .addNode("polish", polish)
  .addEdge(START, "generateOutline")
  .addEdge("generateOutline", "writeDraft")
  .addEdge("writeDraft", "polish")
  .addEdge("polish", END)
  .compile();

const result = await graph.invoke({ topic: "人工智能的日常应用" });

console.log("大纲:", result.outline);
console.log("初稿:", result.draft);
console.log("终稿:", result.final);
```

数据流：

```
START → generateOutline → writeDraft → polish → END
          (写 outline)     (读 outline    (读 draft
                            写 draft)      写 final)
```

## 💡 实战 2：扇出/扇入并行工作流

两个 LLM 并行干活（一个写笑话、一个写诗），结果汇聚后总结。

创建 `fan-out-in.js`：

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

const StateAnnotation = Annotation.Root({
  topic: Annotation,
  // 并行节点都写这个字段 → 必须配 reducer！
  outputs: Annotation({
    reducer: (existing, update) => existing.concat(update),
    default: () => [],
  }),
  summary: Annotation,
});

// 并行节点 1：写笑话
async function writeJoke(state) {
  const res = await model.invoke(`用主题「${state.topic}」写一个 50 字的笑话。`);
  return { outputs: [`【笑话】${res.content}`] };
}

// 并行节点 2：写诗
async function writePoem(state) {
  const res = await model.invoke(`用主题「${state.topic}」写一首 50 字的小诗。`);
  return { outputs: [`【诗歌】${res.content}`] };
}

// 汇聚节点：等两路都完成才执行
async function summarize(state) {
  const res = await model.invoke(
    `下面是两份作品，请各用一句话点评：\n\n${state.outputs.join("\n\n")}`
  );
  return { summary: res.content };
}

const graph = new StateGraph(StateAnnotation)
  .addNode("writeJoke", writeJoke)
  .addNode("writePoem", writePoem)
  .addNode("summarize", summarize)
  // 扇出：两条边从 START 出发 → writeJoke 和 writePoem 并行
  .addEdge(START, "writeJoke")
  .addEdge(START, "writePoem")
  // 扇入：都指向 summarize
  .addEdge("writeJoke", "summarize")
  .addEdge("writePoem", "summarize")
  .addEdge("summarize", END)
  .compile();

const result = await graph.invoke({ topic: "打工人" });

console.log("并行产出:", result.outputs);
console.log("点评:", result.summary);
```

执行结构：

```
            ┌─→ [writeJoke] ─┐
START ──────┤   （并行执行）   ├─→ [summarize] → END
            └─→ [writePoem] ─┘
```

> 💡 **说明：** `invoke()` 会等整张图跑完再返回。如果想看到"每一步"的实时进展，用 `stream()`（第 25 章详解）。

## 🧩 进阶：私有状态与输入/输出过滤（了解即可）

大图里有些中间字段不想暴露给外部（比如只给内部节点用的草稿缓存）。LangGraph 支持给图声明**整体状态、输入模式、输出模式**三套定义，外部只能看到输入/输出模式里声明的字段：

```javascript
const graph = new StateGraph({
  state: OverallStateAnnotation,   // 内部完整状态（所有节点可见）
  input: InputStateAnnotation,     // invoke() 时必须提供的字段
  output: OutputStateAnnotation,   // invoke() 结束后返回的字段子集
});
```

入门阶段用一份状态定义就够了，等图变大、想收敛输入输出时再回来用这个特性。

## ⚠️ 注意事项

### 1. 节点名不能重复

```javascript
// ❌ 错误：重复注册会报错
.addNode("agent", nodeA)
.addNode("agent", nodeB)
```

### 2. 别忘了把每条路都连到 END

```
START → A → B → END    ✅
START → A → B（没有到 END 的边）⚠️ 图可能一直跑不到终点
```

### 3. 循环必须要有出口条件

图的强大在于能循环（如"工具调用 → 再思考 → 再调用"），但循环一定要有终止条件（通常是条件边判断，第 19 章），否则会触发递归上限报错。

### 4. 并行节点写同一字段 = 必须 reducer

详见第 17 章，这是最常见的报错来源。

---

## 📝 本章小结

- 节点 = 函数 `(state, config) => 更新`，支持 async
- `Command({ update, goto })` 可以在节点内同时更新状态和决定去向
- 一个源节点多条出边 = **并行扇出**；多条边汇到一个节点 = **扇入等待**
- 顺序流水线：每个节点读写不同字段即可
- 并行工作流：共享字段必须配 reducer
