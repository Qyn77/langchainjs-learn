## 📖 一句话解释

**LangGraph 是一个低层级的编排框架和运行时，专门用来构建长时运行、有状态的 AI Agent 和工作流。**

如果说 LangChain 帮你"调用模型、组装链"，那 LangGraph 帮你"编排整个流程"——用**图（Graph）**的方式把步骤连起来，支持**循环、分支、并行、暂停恢复**。

---

## 🤔 为什么需要 LangGraph？

### 回顾：我们已经学过的工具

在 LangChain 教程里，我们学过两种组织逻辑的方式：

| 方式 | 代表 API | 特点 | 局限 |
|------|---------|------|------|
| 链 (Chain) | `.pipe()` | 单向流水线，一步接一步 | ❌ 没有循环 |
| 预置 Agent | `createAgent` | 开箱即用的 ReAct 循环 | ❌ 内部流程难定制 |

### 现实中的 Agent 需要什么？

```
用户提问
   │
   ▼
┌──────────┐   需要查资料？   ┌──────────┐
│  思考     │ ───是──→       │ 调用工具  │──┐
└──────────┘                 └──────────┘  │
   ▲                                       │
   │            结果不满意？再试一次        │
   └──────────── 循环 ←────────────────────┘
   │
   ▼
最终回答
```

关键在于：**Agent 的流程不是一条直线，而是一个会"绕圈子"的图**：

- 🔄 **循环**：调用工具后回到"思考"，反复迭代直到满意
- 🔀 **分支**：根据条件走不同的路
- ⏸️ **暂停**：等人类审批后再继续（人机协同）
- 💾 **记住状态**：随时保存进度，崩溃后能恢复

这些用 `.pipe()` 链做不到，用预置 Agent 又不够灵活——**LangGraph 就是为这些场景设计的**。

## 🧱 LangChain vs LangGraph

> ⚠️ **重要提示：** 两者不是竞争关系，而是分工协作。

| 对比项 | LangChain | LangGraph |
|--------|-----------|-----------|
| 定位 | Agent 框架（模型、工具、Prompt 的抽象） | 编排框架和运行时 |
| 抽象层级 | 较高（`createAgent` 一行构建） | 很低（自己画图、自己连线） |
| 适合场景 | 标准的 ReAct 工具调用 Agent | 复杂工作流、多 Agent、需要精细控制 |
| 模型/工具集成 | ✅ 提供 | 可搭配 LangChain 组件使用，也可不用 |

**官方建议：**
- 入门或需要简单工具循环 → 直接用 LangChain 的 `createAgent`（见第 12 章）
- 需要自定义流程、循环、并行、人工审批 → 用 LangGraph

> 💡 **说明：** LangChain 的 `createAgent` 底层就是用 LangGraph 实现的。学了 LangGraph，你也能看懂它内部在做什么。

## 🧱 核心概念（先混个眼熟）

LangGraph 用"图"来描述 Agent 的行为，核心只有三样东西：

```
                    ┌─────────────────────────────┐
                    │         Graph (图)           │
                    │                             │
   输入 ──→ ┌─────────────┐    ┌─────────────┐   │
            │  Node 节点   │───→│  Node 节点   │   │──→ 输出
            │ (干活的函数) │    │ (干活的函数) │   │
            └─────────────┘    └─────────────┘
                   ▲                  │
                   │    Edge 边       │
                   └──(决定下一步走谁)─┘

   所有节点共享一份 State (状态)
```

| 概念 | 是什么 | 类比 |
|------|--------|------|
| **State（状态）** | 所有节点共享的数据结构，随执行不断更新 | 工厂的传送带 |
| **Node（节点）** | 一个函数，接收当前状态，干点活，返回状态更新 | 工位上的工人 |
| **Edge（边）** | 决定一个节点干完后，下一步执行哪个节点 | 传送带的轨道 |
| **Graph（图）** | 节点 + 边组成的整体，`compile()` 后才能运行 | 整个工厂 |
| **Checkpointer（检查点）** | 每一步自动保存状态快照 | 工厂的监控录像 |

> 💡 **一句话记住：** 官方原话是 **"nodes do the work, edges tell what to do next"**——节点干活，边告诉它下一步去哪。

### 执行机制：超级步（Super-step）

LangGraph 底层受 Google Pregel 系统启发，按"超级步"一步步执行：

1. 所有节点一开始处于**待命**状态
2. 收到消息（状态更新）的节点被**激活**
3. 同一个超级步里被激活的节点**并行执行**
4. 没活干的节点退出，全部节点退出时图执行结束

你不需要记住细节，只需知道：**同一个超级步的多个节点会并行跑**（第 17 章会用到）。

## ⚡ LangGraph 的核心能力

| 能力 | 说明 | 对应章节 |
|------|------|---------|
| **持久化执行** | 每步自动存检查点，出错可从上一步恢复 | 第 21 章 |

| **子图/多 Agent** | 图套图，多个 Agent 协作 | 第 23-24 章 |

## 🔀 两种写法：Graph API 与 Functional API

LangGraph 提供两种 API 风格（本教程以 **Graph API** 为主）：

| 对比 | Graph API（图式） | Functional API（函数式） |
|------|------------------|------------------------|
| 核心类/函数 | `StateGraph` + `Annotation` | `entrypoint` + `task` |
| 风格 | 声明式：定义节点和边 | 命令式：普通 if/else + 函数调用 |
| 适合 | 复杂分支、并行、需要可视化的流程 | 改造现有顺序代码、快速原型 |
| 学习曲线 | 稍陡（要理解状态和边） | 平缓 |

> 💡 **说明：** 两者共享同一套运行时（持久化、流式、人机协同都支持），可以在同一个应用里混用。入门先掌握 Graph API，它也是理解 LangChain `createAgent` 内部原理的基础。Functional API 详见[第 27 章](./27-Functional API.md)。

## 🎯 典型应用场景

| 场景 | 说明 | 用到的能力 |
|------|------|-----------|
| 智能客服 | 多轮对话 + 查订单/退款等工具 | 记忆 + 工具 + 条件边 |
| 审批类 Agent | 执行敏感操作前等人工确认 | 人机协同 |
| 深度研究助手 | 搜索→总结→再搜索，循环多轮 | 循环 + 并行 |
| 多专家协作 | 主管分派任务给多个专家 Agent | 子图 + 多 Agent |
| 长时任务 | 跑几小时的数据处理，崩溃可恢复 | 持久化执行 |
