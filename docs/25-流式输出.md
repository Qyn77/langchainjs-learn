# 25-流式输出：实时观察图的每一步

> 📅 适用于 LangGraph.js v1.x | 👶 零基础友好
> 💡 **注意：** 需要 Node.js 18+

---

## 🎯 本章目标

- ✅ 掌握 `stream()` 与各种流模式（streamMode）
- ✅ 用 `messages` 模式实现 LLM 打字机效果
- ✅ 用 `config.writer` 上报自定义进度
- ✅ 了解一次性订阅多种流模式

## 🤔 为什么图更需要流式？

`invoke()` 是"闷头跑完才给结果"，但图的执行往往**很长**（多节点、多轮循环）。用户盯着空白屏幕等 30 秒是不可接受的。

`stream()` 让你实时看到：

- 📊 每个节点执行后的状态变化
- 💬 LLM 正在吐出的每一个 token（打字机效果）
- 📡 节点/工具里主动上报的自定义进度

---

## 📦 stream() 基本用法

```javascript
// stream() 用法和 invoke() 一样，只是返回异步迭代器
for await (const chunk of await graph.stream(input, config)) {
  console.log(chunk);
}
```

关键在第二个参数的 **`streamMode`**，它决定"每次给你什么"：

| streamMode | 给你什么 | 适用场景 |
|-----------|---------|---------|
| `"values"` | 每步之后的**完整状态** | 看全局进展 |
| `"updates"` | 每步的**增量更新**（节点名 + 该节点写了什么） | 观察每个节点干了啥 |
| `"messages"` | LLM 的 **token 流**（元组：`[消息块, 元信息]`） | 打字机效果 |
| `"custom"` | 节点/工具里 `writer()` 主动上报的数据 | 自定义进度条 |
| `"tools"` | 工具调用生命周期事件 | 工具执行进度 |
| `"debug"` | 一切信息 | 调试 |

## 💡 完整示例 1：values / updates 模式

创建 `stream-values.js`：

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  topic: Annotation,
  joke: Annotation,
});

const graph = new StateGraph(StateAnnotation)
  .addNode("refineTopic", (state) => {
    return { topic: state.topic + "（加一点冷幽默）" };
  })
  .addNode("generateJoke", (state) => {
    return { joke: `这是一个关于「${state.topic}」的笑话。` };
  })
  .addEdge(START, "refineTopic")
  .addEdge("refineTopic", "generateJoke")
  .addEdge("generateJoke", END)
  .compile();

// ===== updates 模式：每步只给"变化" =====
console.log("=== updates 模式 ===");
for await (const chunk of await graph.stream(
  { topic: "程序员" },
  { streamMode: "updates" }
)) {
  // chunk 形如 { 节点名: 该节点的更新 }
  for (const [nodeName, update] of Object.entries(chunk)) {
    console.log(`节点 [${nodeName}] 更新:`, update);
  }
}

// ===== values 模式：每步给"完整状态" =====
console.log("\n=== values 模式 ===");
for await (const snapshot of await graph.stream(
  { topic: "程序员" },
  { streamMode: "values" }
)) {
  console.log("当前状态:", snapshot);
}
```

运行效果：

```
=== updates 模式 ===
节点 [refineTopic] 更新: { topic: '程序员（加一点冷幽默）' }
节点 [generateJoke] 更新: { joke: '这是一个关于「程序员（加一点冷幽默）」的笑话。' }

=== values 模式 ===
当前状态: { topic: '程序员' }
当前状态: { topic: '程序员（加一点冷幽默）' }
当前状态: { topic: '程序员（加一点冷幽默）', joke: '...' }
```

## 💬 完整示例 2：messages 模式打字机

`"messages"` 模式能拿到图里**所有 LLM 调用**的 token 流——不管 LLM 在哪个节点、用的是不是 `invoke()`（不需要手动调 `model.stream()`）：

创建 `stream-messages.js`：

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { MessagesAnnotation, StateGraph, START, END } from "@langchain/langgraph";

const model = new ChatOpenAI({
  modelName: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

const graph = new StateGraph(MessagesAnnotation)
  .addNode("callModel", async (state) => {
    const res = await model.invoke(state.messages);  // 注意：用 invoke 也能流式！
    return { messages: [res] };
  })
  .addEdge(START, "callModel")
  .addEdge("callModel", END)
  .compile();

// messages 模式：产出 [消息块, 元信息] 元组
for await (const [chunk, metadata] of await graph.stream(
  { messages: [{ role: "user", content: "用 100 字介绍 LangGraph 的循环能力" }] },
  { streamMode: "messages" }
)) {
  if (chunk.content) {
    process.stdout.write(chunk.content);  // 打字机效果！
  }
}
console.log("\n✅ 输出完成");
```

### 按节点过滤 token

`metadata` 里带着这条 token 来自哪个节点，多节点的图里可以只显示特定节点的输出：

```javascript
for await (const [chunk, metadata] of await graph.stream(input, {
  streamMode: "messages",
})) {
  // 只显示 callModel 节点产出的 token
  if (chunk.content && metadata.langgraph_node === "callModel") {
    process.stdout.write(chunk.content);
  }
}
```

> 💡 **提示：** 想过滤"某个模型的输出"，给模型加 `tags`，然后判断 `metadata.tags`；想隐藏内部模型的输出，给它加 `"nostream"` tag。

## 📡 完整示例 3：custom 模式上报进度

节点内部可以用 `config.writer()` 主动"发弹幕"——比如处理到哪一步了、百分比进度：

创建 `stream-custom.js`：

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  files: Annotation,
  progress: Annotation,
});

async function processFiles(state, config) {
  const files = state.files;
  for (let i = 0; i < files.length; i++) {
    // 模拟处理文件
    await new Promise((r) => setTimeout(r, 300));

    // ★ 主动上报进度（数据类型随意，可 JSON 序列化即可）
    config.writer?.({
      type: "progress",
      current: i + 1,
      total: files.length,
      message: `已处理 ${files[i]}`,
    });
  }
  return { progress: "全部完成" };
}

const graph = new StateGraph(StateAnnotation)
  .addNode("processFiles", processFiles)
  .addEdge(START, "processFiles")
  .addEdge("processFiles", END)
  .compile();

// custom 模式：只收 writer 上报的数据
for await (const data of await graph.stream(
  { files: ["a.txt", "b.txt", "c.txt"] },
  { streamMode: "custom" }
)) {
  console.log(`[${data.current}/${data.total}] ${data.message}`);
}
console.log("✅ 完成");
```

运行效果：

```
[1/3] 已处理 a.txt
[2/3] 已处理 b.txt
[3/3] 已处理 c.txt
✅ 完成
```

> 💡 **说明：** 节点的第二个参数就是 `config`，`writer` 在上面。这是给 Web 应用做"实时进度条"的标准姿势（配合 WebSocket/SSE 推给前端）。

## 🔀 一次订阅多种模式

`streamMode` 传数组即可同时订阅多种流；此时每个 chunk 变成 `[模式名, 数据]` 元组：

```javascript
for await (const [mode, data] of await graph.stream(input, {
  streamMode: ["updates", "custom"],
})) {
  if (mode === "updates") {
    console.log("状态更新:", data);
  } else if (mode === "custom") {
    console.log("自定义进度:", data);
  }
}
```

### 顺便看子图内部

配合第 23 章的子图，加 `subgraphs: true` 就能收到子图内部的事件（chunk 前面会多一个命名空间数组）：

```javascript
for await (const [namespace, update] of await graph.stream(input, {
  streamMode: "updates",
  subgraphs: true,
})) {
  console.log(`[${namespace.join("/") || "父图"}]`, update);
}
```

## ⚠️ 注意事项

### 1. stream 和 invoke 二选一，别混用

同一次执行要么 `invoke` 要么 `stream`。stream 已经拿到了全部输出（最后一步的 `values` 就是最终状态），不需要再 invoke 一遍。

### 2. messages 模式不挑模型的调用方式

节点里用 `model.invoke()` 也照样出 token 流——LangGraph 在底层自动捕获 LLM 事件，这是它比手动 `model.stream()` 方便的地方。

### 3. writer 是可选的

`config.writer?.({...})` 用可选调用最稳妥（普通 Runnable 场景下 config 里可能没有 writer）。

### 4. 前端集成

真实项目里，把 stream 拿到的 chunk 通过 WebSocket / SSE 转发给前端即可，模式和第 05 章（LangChain 流式）的思路一致，只是数据源更丰富（状态更新 + token + 自定义进度都有了）。

---

## 📝 本章小结

- `graph.stream(input, { streamMode })` 返回异步迭代器
- `values`/`updates` 看状态，`messages` 看 LLM token，`custom` 收 `config.writer` 上报
- `messages` 模式产出 `[消息块, 元信息]` 元组，`metadata.langgraph_node` 可按节点过滤
- 多模式用数组订阅，chunk 变成 `[模式名, 数据]`
- 官方还有新式的 `streamEvents` 事件流 API（v1.2+ 推荐），按需进阶
