# Setup and Your First Graph

> 📅 For LangGraph.js v1.x | 👶 Beginner-friendly
> 💡 **Note:** Requires Node.js 18+ (20+ recommended, consistent with the LangChain tutorial)

---

## 🎯 Goals for This Chapter

- ✅ Install the LangGraph dependencies
- ✅ Run your first graph (Hello World)
- ✅ Understand how to build a `StateGraph`: define State → add nodes → connect edges → compile
- ✅ Learn to run a graph with `invoke()`

## 📦 Step 1: Create a Project and Install Dependencies

```bash
# Create the project directory
mkdir my-langgraph-app
cd my-langgraph-app

# Initialize an npm project
npm init -y
```

Add `"type": "module"` to `package.json` so you can use `import` syntax:

```json
{
  "name": "my-langgraph-app",
  "type": "module",
  "dependencies": {}
}
```

Install the dependencies:

```bash
# LangGraph core + LangChain core (required)
npm install @langchain/langgraph @langchain/core

# Model integration (this tutorial uses ModelScope's OpenAI-compatible API)
npm install @langchain/openai
```

### What Each Package Does

| Package | Role | Required |
|------|------|------|
| `@langchain/langgraph` | LangGraph core (`StateGraph`, `MemorySaver`, and more) | ✅ |
| `@langchain/core` | LangChain core abstractions (message types and more) | ✅ |
| `@langchain/openai` | OpenAI-compatible models (including ModelScope) | ✅ when you need an LLM |
| `@langchain/community` | Community tools (search and more) | Optional |

## 🌍 Step 3: Your First Graph (Hello World)

Create `hello.js`:

```javascript
import { MessagesAnnotation, StateGraph, START, END } from "@langchain/langgraph";

// 1. Define a node: it is just an ordinary function
//    It receives the current State and returns a State update
const mockLlm = (state) => {
  return { messages: [{ role: "ai", content: "hello world" }] };
};

// 2. Build the graph
const graph = new StateGraph(MessagesAnnotation)
  .addNode("mock_llm", mockLlm)     // Register the node
  .addEdge(START, "mock_llm")       // Entry edge: START leads into mock_llm
  .addEdge("mock_llm", END)         // Exit edge: the graph ends after mock_llm
  .compile();                       // Compile! It can run only after compilation

// 3. Run the graph
const result = await graph.invoke({
  messages: [{ role: "user", content: "hi!" }],
});

// 4. Look at the result: the final State
console.log(result.messages);
// [
//   HumanMessage { content: "hi!" },
//   AIMessage { content: "hello world" }
// ]
```

Run it:

```bash
node hello.js
```

> 💡 **Note:** Top-level `await` works directly in an ES module. That is why we added `"type": "module"` to `package.json`.

## 🔍 Taking This Graph Apart

### 1. What Is `MessagesAnnotation`?

A graph needs a **State definition** (chapter 17 covers this in detail). `MessagesAnnotation` is the official preset State template. It has a single `messages` field:

```javascript
// MessagesAnnotation is roughly equivalent to:
const StateAnnotation = Annotation.Root({
  messages: Annotation({
    reducer: messagesStateReducer,  // New messages are appended to the list, not overwritten
    default: () => [],
  }),
});
```

"Store a list of conversation messages in State" is so common that the library packages it as `MessagesAnnotation`.

### 2. A Node's Return Value Is a State Update

A node **does not need to return the full State**. It returns only the part that should change:

```javascript
const mockLlm = (state) => {
  // state.messages is the current message list
  // The returned { messages: [...] } is appended to the list by the reducer
  return { messages: [{ role: "ai", content: "hello world" }] };
};
```

### 3. `START` and `END` Are Special Nodes

```javascript
.addEdge(START, "mock_llm")  // START = the graph's entry (internal name "__start__")
.addEdge("mock_llm", END)    // END   = the graph's exit (internal name "__end__")
```

### 4. You Must `compile()` Before It Can Run

`compile()` checks the graph structure (for example, whether any node is isolated) and produces a runnable graph. **Calling invoke without compile throws an error.**

## 🤖 Step 4: Connect a Real LLM

Replace the mock node with a real model call. Create `first-llm.js`:

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { MessagesAnnotation, StateGraph, START, END } from "@langchain/langgraph";

// Create the model (same setup as the LangChain tutorial)
const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

// Node: call the model
async function callModel(state) {
  const response = await model.invoke(state.messages);
  // Return a message list. It will be appended to state.messages
  return { messages: [response] };
}

// Build the graph: START → callModel → END
const graph = new StateGraph(MessagesAnnotation)
  .addNode("callModel", callModel)
  .addEdge(START, "callModel")
  .addEdge("callModel", END)
  .compile();

// Run it
const result = await graph.invoke({
  messages: [{ role: "user", content: "Introduce LangGraph in one sentence" }],
});

console.log("AI reply:", result.messages[result.messages.length - 1].content);
```

> 💡 **Note:** You can pass a plain object `{ role: "user", content: "..." }`. LangGraph converts it into a LangChain message automatically.

What you should see:

```
AI reply: LangGraph is an orchestration framework for building stateful,
multi-step AI applications. It organizes the flow as a graph and supports
loops, branches, and human-in-the-loop.
```

## 🎨 Step 5: Visualize Your Graph

LangGraph can export a graph as a Mermaid image:

```javascript
import { writeFileSync } from "node:fs";

// Get the graph representation and export a PNG
const image = await graph.getGraph().drawMermaidPng();
const arrayBuffer = await image.arrayBuffer();

writeFileSync("graph.png", new Uint8Array(arrayBuffer));
console.log("Saved graph.png");
```

Open `graph.png` and you will see:

```
[START] → [callModel] → [END]
```

> 💡 **Note:** `drawMermaidPng()` needs a network request to the Mermaid rendering service. You can also call `drawMermaid()` to get the Mermaid text and paste it into an editor that supports Mermaid.

## 🆚 Compared with a LangChain Chain

The same "answer in one sentence" task looks like this as a chain (chapter 08) and as a graph:

```javascript
// The chain version (LangChain chapter 08)
const chain = prompt.pipe(model);
const result = await chain.invoke({ topic: "LangGraph" });

// The graph version (this chapter)
const graph = new StateGraph(MessagesAnnotation)
  .addNode("callModel", callModel)
  .addEdge(START, "callModel")
  .addEdge("callModel", END)
  .compile();
const result = await graph.invoke({ messages: [...] });
```

The graph looks a bit more verbose. What you get in return is **a clear execution structure, State management, and the freedom to add loops, branches, and parallelism later**. A chain gets out of hand once it grows complex. A graph does not.

## ⚠️ Common Problems

### 1. Error: `Cannot find module '@langchain/langgraph'`

```bash
npm install
```

### 2. Error: the graph structure is incomplete

```
Error: Node `xxx` is not reachable
```

Cause: some node is not connected to a path that includes START. Check whether an `addEdge` call is missing.

### 3. You forgot to compile

```
TypeError: graph.invoke is not a function
```

`new StateGraph(...)` returns a builder. `invoke` and `stream` exist only after `.compile()`.

### 4. Top-level await fails

```
SyntaxError: await is only valid in async functions
```

Make sure `package.json` contains `"type": "module"`, or wrap the code in `async function main()`.

## 📝 Chapter Summary

- Install: `npm install @langchain/langgraph @langchain/core`
- Four steps to build a graph: **define State → addNode → addEdge → compile**
- `START` and `END` are the special entry and exit nodes
- A node is a function: it receives `state` and returns a **partial update**
- `MessagesAnnotation` is the preset State template for a message list
- `invoke()` runs the graph and returns the final State. `getGraph().drawMermaidPng()` visualizes it
