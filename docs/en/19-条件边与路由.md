## 🤔 Why Do You Need Conditional Edges?

A plain edge has a **fixed** route:

```javascript
.addEdge("A", "B")  // B always follows A
```

A real Agent has to decide from the **current State**:

```
                         ┌─ Need to look something up? ─→ [call a tool] ─┐
[model thinks] ──────────┤                                               │
                         └─ No ──→ [answer directly] ←── loop back
```

Whether to call a tool is something you only know at runtime. That is what a **conditional edge** is for.

---

## 📦 Basic Usage of addConditionalEdges

```javascript
graph.addConditionalEdges(sourceNode, routerFunction);
```

- `sourceNode`: which node this edge leaves from
- `routerFunction`: the router. It receives the current State and **returns the name of the next node** (or `END`)

### Rules for the router

```javascript
const router = (state) => {
  if (/* condition 1 */) return "nodeA";   // return a node name
  if (/* condition 2 */) return ["b1", "b2"]; // an array means several paths in parallel
  return END;                          // or end the graph
};
```

## 💡 Full Example 1: An Intent-Routing Support Bot

Route to a different handler based on keywords in the user's question. This runs without an LLM, so you can get the structure working first.

> 💡 **Key point:** A conditional edge is attached where you leave a node. To branch **at the entry**, the usual pattern is: point `START` at a passthrough node, then attach the conditional edge after that node.

Create `intent-router.js`:

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  question: Annotation,   // the user's question
  answer: Annotation,     // the reply
});

// Router: read State and return the next node's name
function routeIntent(state) {
  const q = state.question;
  if (q.includes("refund") || q.includes("order")) return "billing";
  if (q.includes("error") || q.includes("bug")) return "technical";
  return "general";
}

const graph = new StateGraph(StateAnnotation)
  .addNode("billing", (state) => ({
    answer: `[Billing] We received your question: "${state.question}". We will process your refund.`,
  }))
  .addNode("technical", (state) => ({
    answer: `[Tech support] About "${state.question}": try restarting, then clear the cache.`,
  }))
  .addNode("general", (state) => ({
    answer: `[Human support] Your question has been logged. Someone will reply shortly.`,
  }))
  .addEdge(START, "router")           // entry goes to router first
  .addNode("router", (state) => ({})) // the router node does not update State; it only passes through
  .addConditionalEdges("router", routeIntent)  // after router, branch on State
  .addEdge("billing", END)
  .addEdge("technical", END)
  .addEdge("general", END)
  .compile();

// Test
console.log((await graph.invoke({ question: "I want a refund" })).answer);
// [Billing] We received your question: "I want a refund". We will process your refund.

console.log((await graph.invoke({ question: "The page shows an error" })).answer);
// [Tech support] About "The page shows an error": try restarting, then clear the cache.

console.log((await graph.invoke({ question: "Hello there" })).answer);
// [Human support] Your question has been logged. Someone will reply shortly.
```

## 🔀 Let an LLM Make the Routing Decision

Replace keyword matching with an LLM judgment and you get the common "semantic routing" pattern:

```javascript
async function routeIntent(state) {
  const res = await model.invoke(
    `Classify the user's question. Return only one word (billing/technical/general):\n${state.question}`
  );
  const category = res.content.trim();
  return ["billing", "technical", "general"].includes(category)
    ? category
    : "general";  // fallback: if the model output is unreliable, take the default branch
}
```

> 💡 **Tip:** A router can be `async`. Routing should still be as fast as possible. Skip the LLM when you can (it saves time and money). If a simple rule solves it, use the rule.

## 🗺️ pathMap: Mapping Router Results

A router can also return any key, and a third argument maps that key to the real node name:

```javascript
.addConditionalEdges(
  "check",
  (state) => (state.ok ? "yes" : "no"),   // return a key
  { yes: "goodNode", no: "badNode" }      // map of key → node name
)
```

> 💡 **Note:** Returning the node name directly (as in example 1) is the clearest style, and it is the one to start with. pathMap fits when the router should not know the concrete node names.

## 📤 Send: Dynamic Dispatch (Map-Reduce)

A conditional edge picks a path each time it runs. What if you want to **launch N parallel tasks at once**? For example:

> "Write one joke for each of 5 topics" → launch 5 parallel "write a joke" nodes, and give each one a different input.

That is what `Send` does: **the router returns several `Send` objects. Each `Send` names a target node and the input reserved for that run.**

```javascript
import { Send } from "@langchain/langgraph";

function dispatchJobs(state) {
  // One Send per topic: Send(target node name, input for that run)
  return state.topics.map((topic) => new Send("writeJoke", { topic }));
}

graph.addConditionalEdges("generateTopics", dispatchJobs);
```

### Full example

Create `map-reduce.js`:

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { Annotation, StateGraph, START, END, Send } from "@langchain/langgraph";

const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

const StateAnnotation = Annotation.Root({
  topics: Annotation,           // list of topics
  jokes: Annotation({           // collect every joke → this field must have a reducer
    reducer: (existing, update) => existing.concat(update),
    default: () => [],
  }),
});

// Node 1: generate topics (this could also be a hard-coded list)
async function generateTopics(state) {
  const res = await model.invoke("Give me 3 topics that work well for jokes. Separate them with commas, and return only the topics.");
  return { topics: res.content.split(",").map((t) => t.trim()) };
}

// Node 2: write a joke (runs many times in parallel; each run receives a different topic)
async function writeJoke(input) {
  // Note: the second argument to Send is this node's input (not the whole graph State)
  const res = await model.invoke(`Write a 50-word joke on the topic "${input.topic}".`);
  return { jokes: [res.content] };
}

// Router: turn the topic list into N parallel tasks
function dispatchJobs(state) {
  return state.topics.map((topic) => new Send("writeJoke", { topic }));
}

const graph = new StateGraph(StateAnnotation)
  .addNode("generateTopics", generateTopics)
  .addNode("writeJoke", writeJoke)
  .addEdge(START, "generateTopics")
  .addConditionalEdges("generateTopics", dispatchJobs)
  .addEdge("writeJoke", END)
  .compile();

const result = await graph.invoke({});
console.log(`Generated ${result.jokes.length} jokes:`);
result.jokes.forEach((j, i) => console.log(`${i + 1}. ${j}`));
```

The important part:

```
generateTopics returns { topics: ["cats", "work", "takeout"] }
        │
        ▼ dispatchJobs sends them out
   ┌─ Send(writeJoke, {topic:"cats"}) ────→ writeJoke ─┐
   ├─ Send(writeJoke, {topic:"work"}) ────→ writeJoke ─┼─→ each one goes to END when it finishes
   └─ Send(writeJoke, {topic:"takeout"}) ─→ writeJoke ─┘
                          (three run in parallel; jokes are collected by the reducer)
```

> ⚠️ **Note:** For a node launched by `Send`, the function argument is **the second argument of `Send`** (the input reserved for that task), not the graph's global State. Collecting results still uses a field with a reducer.

## 🔁 The Recursion Limit: recursionLimit

A graph can loop, but the number of loops has a cap. LangGraph runs at most **25** supersteps by default. Past that, it throws `GraphRecursionError`:

```javascript
import { GraphRecursionError } from "@langchain/langgraph";

try {
  await graph.invoke(input, { recursionLimit: 50 });  // raise the limit
} catch (e) {
  if (e instanceof GraphRecursionError) {
    console.log("Hit the execution step limit");
  }
}
```

> 💡 **Note:** Passing through one node counts as one step. Agent-style graphs (the model and tools looping back and forth) burn through steps quickly. When the loop is long, raise this value.

## 🆚 Conditional Edges or Command?

| Situation | Use this |
|------|------|
| Pick one path from State, and the logic should be reusable | A conditional edge plus a router |
| Decide the next node while a node is running (the result picks the destination) | The node returns `Command({ goto })` |
| Spawn N parallel tasks at once (each with different input) | `Send` |
| A fixed route | A plain edge, `addEdge` |

## ⚠️ Things to Watch Out For

### 1. The node name the router returns must already be registered

```javascript
// ❌ The router returns "billing" but the graph never called addNode("billing", ...)
// Runtime error: Node `billing` is unknown
```

### 2. Use the END constant. Do not hard-code the string

```javascript
return END;        // ✅ Preferred. Equivalent to "__end__"
return "__end__";  // Works, but harder to read
```

### 3. Give the Send target a reducer field so it can collect results

Parallel writes to the same field with no reducer throw immediately (Chapter 17).

### 4. Keep the router function "pure"

Do not do heavy work inside the router (such as reading and writing large files). It runs on every step. Skip LLM calls when you can.
