# 25-Streaming: Watch Every Step of the Graph in Real Time

> 📅 For LangGraph.js v1.x | 👶 Beginner-friendly
> 💡 **Note:** Requires Node.js 18+

---

## 🎯 Goals for This Chapter

- ✅ Master `stream()` and the stream modes (`streamMode`)
- ✅ Use `messages` mode for an LLM typewriter effect
- ✅ Use `config.writer` to report custom progress
- ✅ Learn how to subscribe to several stream modes at once

---

## 🤔 Why Do Graphs Need Streaming Even More?

`invoke()` runs all the way through and only then gives you a result. Graph runs are often **long** (many nodes, many loop turns). Making a user stare at a blank screen for 30 seconds is not acceptable.

`stream()` lets you see, in real time:

- 📊 The state change after each node runs
- 💬 Every token the LLM is producing (the typewriter effect)
- 📡 Custom progress that a node or tool reports on purpose

---

## 📦 Basic Usage of stream()

```javascript
// stream() is used like invoke(), except it returns an async iterator
for await (const chunk of await graph.stream(input, config)) {
  console.log(chunk);
}
```

The key is **`streamMode`** on the second argument. It decides "what you get each time":

| streamMode | What you get | When to use it |
|------------|--------------|----------------|
| `"values"` | The **full state** after each step | Watch overall progress |
| `"updates"` | The **incremental update** for each step (node name + what that node wrote) | See what each node did |
| `"messages"` | The LLM **token stream** (a tuple: `[message chunk, metadata]`) | Typewriter effect |
| `"custom"` | Data that a node or tool reports on purpose with `writer()` | A custom progress bar |
| `"tools"` | Tool-call lifecycle events | Tool execution progress |
| `"debug"` | Everything | Debugging |

## 💡 Full Example 1: values / updates Mode

Create `stream-values.js`:

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  topic: Annotation,
  joke: Annotation,
});

const graph = new StateGraph(StateAnnotation)
  .addNode("refineTopic", (state) => {
    return { topic: state.topic + " (with a bit of dry humor)" };
  })
  .addNode("generateJoke", (state) => {
    return { joke: `Here is a joke about "${state.topic}".` };
  })
  .addEdge(START, "refineTopic")
  .addEdge("refineTopic", "generateJoke")
  .addEdge("generateJoke", END)
  .compile();

// ===== updates mode: each step gives you only the "change" =====
console.log("=== updates mode ===");
for await (const chunk of await graph.stream(
  { topic: "programmers" },
  { streamMode: "updates" }
)) {
  // chunk looks like { nodeName: that node's update }
  for (const [nodeName, update] of Object.entries(chunk)) {
    console.log(`Node [${nodeName}] update:`, update);
  }
}

// ===== values mode: each step gives you the "full state" =====
console.log("\n=== values mode ===");
for await (const snapshot of await graph.stream(
  { topic: "programmers" },
  { streamMode: "values" }
)) {
  console.log("Current state:", snapshot);
}
```

Sample output:

```
=== updates mode ===
Node [refineTopic] update: { topic: 'programmers (with a bit of dry humor)' }
Node [generateJoke] update: { joke: 'Here is a joke about "programmers (with a bit of dry humor)".' }

=== values mode ===
Current state: { topic: 'programmers' }
Current state: { topic: 'programmers (with a bit of dry humor)' }
Current state: { topic: 'programmers (with a bit of dry humor)', joke: '...' }
```

## 💬 Full Example 2: A Typewriter with messages Mode

`"messages"` mode gives you the token stream of **every LLM call in the graph** — no matter which node the LLM is in, and whether or not that node uses `invoke()` (you do not need to call `model.stream()` yourself):

Create `stream-messages.js`:

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { MessagesAnnotation, StateGraph, START, END } from "@langchain/langgraph";

const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

const graph = new StateGraph(MessagesAnnotation)
  .addNode("callModel", async (state) => {
    const res = await model.invoke(state.messages);  // note: invoke can still stream!
    return { messages: [res] };
  })
  .addEdge(START, "callModel")
  .addEdge("callModel", END)
  .compile();

// messages mode: yields [message chunk, metadata] tuples
for await (const [chunk, metadata] of await graph.stream(
  { messages: [{ role: "user", content: "In about 100 words, introduce LangGraph's ability to loop" }] },
  { streamMode: "messages" }
)) {
  if (chunk.content) {
    process.stdout.write(chunk.content);  // typewriter effect!
  }
}
console.log("\n✅ Output complete");
```

### Filter Tokens by Node

`metadata` records which node this token came from. In a graph with several nodes, you can show output from only one node:

```javascript
for await (const [chunk, metadata] of await graph.stream(input, {
  streamMode: "messages",
})) {
  // Show only tokens produced by the callModel node
  if (chunk.content && metadata.langgraph_node === "callModel") {
    process.stdout.write(chunk.content);
  }
}
```

> 💡 **Tip:** To filter "one model's output," add `tags` to the model and check `metadata.tags`. To hide an internal model's output, give it a `"nostream"` tag.

## 📡 Full Example 3: Report Progress with custom Mode

Inside a node you can call `config.writer()` to push a live update — which step you are on, or a percent complete:

Create `stream-custom.js`:

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  files: Annotation,
  progress: Annotation,
});

async function processFiles(state, config) {
  const files = state.files;
  for (let i = 0; i < files.length; i++) {
    // Simulate processing a file
    await new Promise((r) => setTimeout(r, 300));

    // ★ Report progress on purpose (any JSON-serializable data is fine)
    config.writer?.({
      type: "progress",
      current: i + 1,
      total: files.length,
      message: `Processed ${files[i]}`,
    });
  }
  return { progress: "All done" };
}

const graph = new StateGraph(StateAnnotation)
  .addNode("processFiles", processFiles)
  .addEdge(START, "processFiles")
  .addEdge("processFiles", END)
  .compile();

// custom mode: receive only the data that writer reports
for await (const data of await graph.stream(
  { files: ["a.txt", "b.txt", "c.txt"] },
  { streamMode: "custom" }
)) {
  console.log(`[${data.current}/${data.total}] ${data.message}`);
}
console.log("✅ Done");
```

Sample output:

```
[1/3] Processed a.txt
[2/3] Processed b.txt
[3/3] Processed c.txt
✅ Done
```

> 💡 **Explanation:** The node's second argument is `config`, and `writer` lives on it. This is the standard way to build a live progress bar for a web app (push updates to the frontend over WebSocket or SSE).

## 🔀 Subscribe to Several Modes at Once

Pass an array to `streamMode` to subscribe to several streams at the same time. Each chunk then becomes a `[mode name, data]` tuple:

```javascript
for await (const [mode, data] of await graph.stream(input, {
  streamMode: ["updates", "custom"],
})) {
  if (mode === "updates") {
    console.log("State update:", data);
  } else if (mode === "custom") {
    console.log("Custom progress:", data);
  }
}
```

### Peek Inside a Subgraph While You Are at It

Together with the subgraphs from Chapter 23, `subgraphs: true` lets you receive events from inside the subgraph (an extra namespace array is prepended to each chunk):

```javascript
for await (const [namespace, update] of await graph.stream(input, {
  streamMode: "updates",
  subgraphs: true,
})) {
  console.log(`[${namespace.join("/") || "parent"}]`, update);
}
```

## ⚠️ Things to Watch Out For

### 1. Pick stream or invoke for one run; do not mix them

One execution is either `invoke` or `stream`. A stream already has the full output (the last `values` step is the final state), so you do not need to `invoke` again.

### 2. messages mode does not care how you call the model

A node that uses `model.invoke()` still produces a token stream. LangGraph captures LLM events underneath, which is why this is more convenient than calling `model.stream()` yourself.

### 3. writer is optional

`config.writer?.({...})` with optional chaining is the safest form (in an ordinary Runnable, `config` may not have a `writer`).

### 4. Frontend integration

In a real project, forward the chunks from the stream to the frontend over WebSocket or SSE. The idea matches Chapter 05 (LangChain streaming). The data source is just richer: you now have state updates, tokens, and custom progress.

## 📝 Chapter Summary

- `graph.stream(input, { streamMode })` returns an async iterator
- `values` and `updates` show state, `messages` shows LLM tokens, and `custom` receives what `config.writer` reports
- `messages` mode yields `[message chunk, metadata]` tuples, and `metadata.langgraph_node` lets you filter by node
- Subscribe to several modes with an array; each chunk becomes `[mode name, data]`
- There is also a newer `streamEvents` event-stream API (recommended in v1.2+). Move on to it when you need it
