## 🤔 Why Do You Need Human-in-the-Loop?

The more autonomous an Agent is, the larger the risk. You would not want AI to do these on its own:

- 💸 Issue a refund, place an order, or transfer money
- 📧 Send a mass email, or publish a public announcement
- 🗑️ Delete data, or change production configuration

**Human-in-the-loop** works like this: when the graph reaches a critical node, it **pauses**, hands the information to a person, and continues only after that person **approves, edits, or rejects**.

The mechanism LangGraph provides is called **`interrupt`**.

---

## 📦 The Three Ingredients of interrupt

```javascript
import { interrupt, Command, MemorySaver } from "@langchain/langgraph";
```

| Ingredient | What it means |
|------|------|
| 1. **Checkpointer** | Pausing means saving the scene, so you need a checkpoint (Chapter 21) |
| 2. **thread_id** | Resume uses it to find the State saved last time |
| 3. **The `interrupt()` call** | Called inside a node. The graph pauses immediately and hands the value to the caller |

How it works:

```
The node reaches interrupt(question)
      │
      1️⃣ The graph pauses. State is already stored in a checkpoint
      2️⃣ The value of interrupt(question) is handed to the caller (result.__interrupt__)
      │
      …… (the person thinks and approves; the graph waits quietly) ……
      │
Call graph.invoke(new Command({ resume: the person's reply }), config)
      │
      3️⃣ The node runs again from the top
      4️⃣ This time interrupt() does not pause. It returns the resume value
      │
      ▼
   The node continues
```

> ⚠️ **Key point:** On resume, the node **runs again from the top**. The return value of `interrupt()` is the value passed to `Command({ resume })`.

## 💡 Full Example: An Order-Approval Flow

This simulates "AI places the order for you, but a person must confirm before it goes through."

Create `approval-flow.js`:

```javascript
import {
  Annotation, StateGraph, START, END,
  MemorySaver, interrupt, Command,
} from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  item: Annotation,        // item to buy
  price: Annotation,       // price
  approved: Annotation,    // whether it was approved
  orderResult: Annotation, // order result
});

// Node 1: prepare the order
function prepareOrder(state) {
  console.log("📦 Preparing order:", state.item, "price:", state.price);
  return {};
}

// Node 2: human approval — the key node!
function humanApproval(state) {
  // Pause execution and hand the approval request to the caller
  // The payload must be JSON-serializable
  const decision = interrupt({
    question: "Do you approve this order?",
    item: state.item,
    price: state.price,
  });
  // First run: execution pauses here; the code below does not run
  // On resume: decision is the value passed to Command({ resume: ... })

  console.log("👤 Human decision:", decision);
  return { approved: decision.approved };
}

// Node 3: place the order
function placeOrder(state) {
  console.log("✅ Order submitted:", state.item);
  return { orderResult: `${state.item} ordered successfully` };
}

// Node 4: cancel
function cancelOrder(state) {
  console.log("🚫 The user cancelled the order");
  return { orderResult: "Order cancelled" };
}

// Build the graph
const graph = new StateGraph(StateAnnotation)
  .addNode("prepareOrder", prepareOrder)
  .addNode("humanApproval", humanApproval)
  .addNode("placeOrder", placeOrder)
  .addNode("cancelOrder", cancelOrder)
  .addEdge(START, "prepareOrder")
  .addEdge("prepareOrder", "humanApproval")
  // After approval, branch on the result
  .addConditionalEdges("humanApproval", (state) =>
    state.approved ? "placeOrder" : "cancelOrder"
  )
  .addEdge("placeOrder", END)
  .addEdge("cancelOrder", END)
  // A checkpointer is required!
  .compile({ checkpointer: new MemorySaver() });

const config = { configurable: { thread_id: "order-1001" } };

// ===== First call: pauses when it reaches the approval node =====
const result1 = await graph.invoke(
  { item: "mechanical keyboard", price: 599 },
  config
);

// Inspect the pause info: the result.__interrupt__ array
const interruptInfo = result1.__interrupt__[0];
console.log("\n⏸️ Graph paused, waiting for human approval:");
console.log(interruptInfo.value);
// { question: "Do you approve this order?", item: "mechanical keyboard", price: 599 }

// ===== Human approval (in real life this might be hours, or even days, later) =====

// Approve: resume with Command({ resume })
const result2 = await graph.invoke(
  new Command({ resume: { approved: true, reason: "The price is fair. Buy it!" } }),
  config
);

console.log("\nFinal result:", result2.orderResult);
// ✅ Order submitted: mechanical keyboard
// Final result: mechanical keyboard ordered successfully
```

If the person wants to reject, swap the resume value:

```javascript
// Reject
await graph.invoke(
  new Command({ resume: { approved: false, reason: "Too expensive" } }),
  config
);
// The graph takes the cancelOrder branch → "Order cancelled"
```

---

## 🔍 Walkthrough of the Node Execution

```
First invoke:
  prepareOrder ✅ → humanApproval runs until interrupt() → ⏸️ pause
  The return value result1.__interrupt__ carries the approval request

Second invoke (Command resume):
  Load the checkpoint → humanApproval runs again from the top
  → this time interrupt() returns immediately with { approved: true, ... }
  → the conditional edge branches → placeOrder → END
```

> 💡 **Note:** `__interrupt__` is an array. If several nodes pause in the same superstep, it holds several interrupt entries. Each one has an `id`, and on resume you can supply a value for each.

## 🛠️ Using interrupt Inside a Tool

The ReAct Agent from Chapter 20 can require human approval too. Call `interrupt` directly inside the **tool function**. Every time the model wants to use that tool, execution pauses until a person approves:

```javascript
import { tool } from "@langchain/core/tools";
import { interrupt, Command } from "@langchain/langgraph";
import { z } from "zod";

const sendEmailTool = tool(
  async ({ to, subject }) => {
    // Pause and wait for human approval
    const response = interrupt({
      action: "send_email",
      to,
      subject,
    });

    if (response?.approved) {
      return `Email sent to ${to}. Subject: ${subject}`;
    }
    return "The user cancelled sending";
  },
  {
    name: "send_email",
    description: "Send an email to the given address (requires human approval before sending)",
    schema: z.object({
      to: z.string().describe("Recipient email address"),
      subject: z.string().describe("Email subject"),
    }),
  }
);
```

Use it with `createReactAgent`:

```javascript
const agent = createReactAgent({
  llm: model,
  tools: [sendEmailTool],
  checkpointSaver: new MemorySaver(),  // interrupt requires a checkpointer
});

// First call: the model decides to send email → interrupt inside the tool pauses
let result = await agent.invoke(
  { messages: [new HumanMessage("Send a leave-request email to boss@company.com")] },
  { configurable: { thread_id: "email-1" } }
);
console.log(result.__interrupt__[0].value);
// { action: "send_email", to: "boss@company.com", subject: "..." }

// Resume after the person approves
result = await agent.invoke(
  new Command({ resume: { approved: true } }),
  { configurable: { thread_id: "email-1" } }
);
```

## ⚠️ Four Hard Rules for interrupt

The official docs list these rules explicitly. Break them and you get strange bugs:

### 1. Do not wrap interrupt() in try/catch

```javascript
// ❌ Wrong: interrupt pauses by throwing a special error internally. catch breaks that
try {
  const answer = interrupt("question");
} catch (e) { /* ... */ }

// ✅ Right: keep interrupt outside try/catch
const answer = interrupt("question");
```

### 2. Do not move interrupt calls around inside a node

On resume the node reruns from the top. If the order or the number of `interrupt()` calls differs between the two runs, resume values land in the wrong place. **Interrupt logic must be fixed and stable.**

### 3. The return value of interrupt should be simple, and the resume value must be JSON-serializable

Both the payload and the resume value are stored in the checkpoint. Strings, numbers, and plain objects are fine. Functions and class instances cause problems.

### 4. Side effects before interrupt must be idempotent

Because the node **reruns from the top** on resume, code before `interrupt` runs again:

```javascript
// ❌ Dangerous: after resume, count is incremented twice
function badNode(state) {
  const total = state.count + 1;      // this runs again
  const ok = interrupt("Continue?");  // the pause point
  return { count: total };
}

// ✅ Safe: put the side effect after interrupt, or make a repeated run harmless
function goodNode(state) {
  const ok = interrupt("Continue?");  // pause first
  return { count: state.count + 1 };  // runs only after approval
}
```

## 📝 Chapter Summary

- `interrupt(payload)` pauses the graph and raises a question. It requires a **checkpointer + thread_id**
- Pause info is in the `__interrupt__` array on the return value
- Invoke again with `new Command({ resume: value })` as the input to resume. That resume value is what `interrupt()` returns
- On resume the node **reruns from the top** → code before interrupt must be idempotent
- You can put interrupt inside a tool function to require approval for sensitive actions in a ReAct Agent
