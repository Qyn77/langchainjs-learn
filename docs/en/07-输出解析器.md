# 07-Output Parsers: Structured Output

> 💡 **Note:** This tutorial uses Zod v4 (`zod@^4.3.6`). The basic API is the same as v3.

## 🎯 Chapter Goals

- ✅ Learn the **recommended approach**: `withStructuredOutput()` returns a structured object directly
- ✅ Learn the fallback approach: parse JSON by hand and validate it with Zod
- ✅ Choose the right structured-output approach for the situation

---

## 🤔 Why Do You Need Output Parsers?

### Without a parser

```javascript
const response = await model.invoke([
  new HumanMessage("Please return JSON that includes a name and an age")
]);

console.log(response.content);
// Output: {
//   "name": "Ming",
//   "age": 25
// }

// ❌ Problem: this is a string, not a real object!
// You have to call JSON.parse() yourself, and parsing can fail
```

### With structured output

LangChain provides two ways to get structured output:

```javascript
// ✅ Approach 1 (recommended): withStructuredOutput — you get a validated object directly
const structuredModel = model.withStructuredOutput(schema);
const result = await structuredModel.invoke("Please extract the person's information");
// result is already { name: "Sam", age: 28, ... }. No manual parsing!

// 🔧 Approach 2 (fallback): parse by hand and validate with Zod
const parsed = schema.parse(JSON.parse(response.content));
```

| Comparison | Approach 1: `withStructuredOutput` | Approach 2: manual parsing |
|------|------------------------------|----------------|
| How it works | Under the hood, **tool calling** forces the model to follow the schema | A prompt convention, plus regex extraction, plus JSON.parse |
| Reliability | High (the framework enforces the schema) | Moderate (extra text from the model can make parsing fail) |
| When to use | When the model supports tool calling (most modern models) | Edge cases where the model does not support tool calling |
| Requirements | Pass a Zod schema or a JSON Schema | You write the extraction and error-handling logic yourself |

## 🚀 Approach 1 (recommended): withStructuredOutput

`withStructuredOutput()` is the standard way to get structured output from a model in LangChain v1.x. Pass a Zod schema and you get a "structured" model. Calling it returns an object that is **already parsed and validated**.

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { HumanMessage } from "@langchain/core/messages";
import { z } from "zod";

const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  temperature: 0,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

// Step 1: define a Zod schema (describe helps the model understand each field)
const personSchema = z.object({
  name: z.string().describe("the person's name"),
  age: z.number().describe("age"),
  occupation: z.string().describe("occupation"),
});

// Step 2: bind structured output
const structuredModel = model.withStructuredOutput(personSchema);

// Step 3: call it — you get an object directly. No JSON.parse!
const result = await structuredModel.invoke([
  new HumanMessage("Sam is 28 years old and works as a software engineer"),
]);

console.log(result);
// { name: "Sam", age: 28, occupation: "software engineer" }
console.log(typeof result.age);  // number — the types are correct
```

### How does it work?

`withStructuredOutput` turns the schema you pass in into a **tool definition**. Tool calling forces the model to return that structure, and the framework parses and validates the result for you. So:

- ✅ You do not have to write prompts like "return JSON only"
- ✅ You do not need a regex, and an extra sentence from the model will not break parsing
- ✅ The output is validated against the schema, so the types are reliable

### Common options

```javascript
// To receive both the raw message and the parsed result:
const structuredModel = model.withStructuredOutput(personSchema, {
  includeRaw: true,
});
const { raw, parsed } = await structuredModel.invoke("...");
```

> 💡 **Prerequisite:** The model must support tool calling (most modern models do, including MiniMax-M2.5 in this tutorial). If the model does not support tool calling, use Approach 2 below and parse the output yourself.
>
> 💡 **Agent use case:** If you are using `createAgent` from Chapter 12, you can pass `responseFormat` to get structured output (the result is in `result.structuredResponse`). See the official docs: [Structured output](https://docs.langchain.com/oss/javascript/langchain/structured-output).

## 🔧 Approach 2 (fallback): parse JSON by hand and validate with Zod

When the model does not support tool calling, or you want full control over parsing, use a prompt convention, parse the JSON yourself, and validate it with Zod:

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { HumanMessage, SystemMessage } from "@langchain/core/messages";
import { z } from "zod";

async function main() {
  const model = new ChatOpenAI({
    model: "MiniMax/MiniMax-M2.5",
    apiKey: process.env.MODELSCOPE_API_KEY,
    temperature: 0,  // use 0 for structured output
    configuration: {
      baseURL: "https://api-inference.modelscope.cn/v1",
    },
  });

  // Step 1: define the output schema (a Zod schema)
  const personSchema = z.object({
    name: z.string().describe("the person's name"),
    age: z.number().describe("age"),
    occupation: z.string().describe("occupation")
  });

  // Step 2: create a prompt that tells the model to return JSON
  const messages = [
    new SystemMessage("You are a data extraction assistant. Extract information from the text and return JSON only, with no other content."),
    new HumanMessage(`
Extract the person's information from the following text and return JSON:
{
  "name": "name",
  "age": age (a number),
  "occupation": "occupation"
}

Text: Sam is 28 years old and works as a software engineer
`)
  ];

  // Step 3: call the model
  const response = await model.invoke(messages);
  console.log("Raw AI reply:", response.content);

  // Step 4: parse the JSON by hand
  try {
    // Extract the JSON portion (it may be wrapped in a code block)
    const jsonMatch = response.content.match(/\{[\s\S]*\}/);
    const jsonStr = jsonMatch ? jsonMatch[0] : response.content;
    const result = JSON.parse(jsonStr);
    
    // Step 5: validate with Zod
    const validated = personSchema.parse(result);
    
    console.log("\n✅ Parsed successfully!");
    console.log("Name:", validated.name);
    console.log("Age:", validated.age);
    console.log("Occupation:", validated.occupation);
  } catch (e) {
    console.error("Parsing failed:", e.message);
  }
}

main();
```

## 📋 Common Zod Types

| Zod type | Description | Example |
|----------|------|------|
| `z.string()` | String | `z.string().email()` |
| `z.number()` | Number | `z.number().min(0).max(100)` |
| `z.boolean()` | Boolean | `z.boolean()` |
| `z.array()` | Array | `z.array(z.string())` |
| `z.enum()` | Enum | `z.enum(["positive", "negative", "neutral"])` |
| `z.object()` | Object | `z.object({ name: z.string() })` |
| `z.optional()` | Optional | `z.string().optional()` |
| `z.null()` | Can be null | `z.string().null()` |

## 🔧 Chaining (manual parsing version)

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { HumanMessage, SystemMessage } from "@langchain/core/messages";
import { PromptTemplate } from "@langchain/core/prompts";
import { z } from "zod";

async function main() {
  const model = new ChatOpenAI({
    model: "MiniMax/MiniMax-M2.5",
    apiKey: process.env.MODELSCOPE_API_KEY,
    temperature: 0,
    configuration: {
      baseURL: "https://api-inference.modelscope.cn/v1",
    },
  });

  // Define the schema
  const schema = z.object({
    term: z.string(),
    definition: z.string(),
    example: z.string()
  });

  // Create the prompt
  const prompt = PromptTemplate.fromTemplate(
    "Explain what {topic} is in JSON format, with the three fields term, definition, and example. Return JSON only, with no other content."
  );

  // Create the chain: Prompt → Model
  const chain = prompt.pipe(model);

  // Call it
  const response = await chain.invoke({ topic: "machine learning" });
  
  // Parse by hand
  const jsonMatch = response.content.match(/\{[\s\S]*\}/);
  const jsonStr = jsonMatch ? jsonMatch[0] : response.content;
  const result = schema.parse(JSON.parse(jsonStr));
  
  console.log("Term:", result.term);
  console.log("Definition:", result.definition);
  console.log("Example:", result.example);
}

main();
```

  confidence: z.number().min(0).max(1),

const messages = [
  new SystemMessage("Analyze the sentiment of the following text. Return JSON only."),

Analyze the sentiment of the following text and return JSON:

const response = await model.invoke(messages);

## ⚠️ Notes

### 1. Set temperature to 0

Structured output needs to be deterministic:

```javascript
const model = new ChatOpenAI({
  temperature: 0,  // ✅ recommended
  // ...
});
```

### 2. Explicitly ask for JSON

```javascript
// ✅ A good prompt
new SystemMessage("Return JSON only, with no other content.")

// ❌ A weak prompt
new SystemMessage("Please analyze this...")  // the model may return extra text
```

### 3. Handle parsing errors

```javascript
try {
  const jsonMatch = response.content.match(/\{[\s\S]*\}/);
  const result = JSON.parse(jsonMatch[0]);
  const validated = schema.parse(result);
} catch (e) {
  console.error("Parsing failed:", e.message);
  // You can retry or return a default value
}
```

### 4. Handle code blocks

The model may wrap the JSON in a Markdown code block:

```javascript
// The reply might look like: ```json {...} ```
const jsonStr = response.content
  .replace(/```json\s*/g, '')
  .replace(/```\s*/g, '')
  .trim();
```

## 📊 A Complete Helper Function

```javascript
import { z } from "zod";

/**
 * Parse and validate JSON returned by the AI
 * @param {string} content - the AI's raw reply
 * @param {z.ZodSchema} schema - the Zod validation schema
 * @returns {object} the validated object
 */
function parseStructuredOutput(content, schema) {
  try {
    // 1. Extract the JSON portion
    const jsonMatch = content.match(/\{[\s\S]*\}/);
    if (!jsonMatch) {
      throw new Error("No JSON content found");
    }
    
    // 2. Strip Markdown code fences
    let jsonStr = jsonMatch[0]
      .replace(/```json\s*/g, '')
      .replace(/```\s*/g, '')
      .trim();
    
    // 3. Parse the JSON
    const parsed = JSON.parse(jsonStr);
    
    // 4. Validate with Zod
    return schema.parse(parsed);
  } catch (e) {
    console.error("Parsing failed:", e.message);
    throw e;
  }
}

// Usage
const result = parseStructuredOutput(response.content, personSchema);
```

## 📝 Chapter Summary

- **Prefer `withStructuredOutput(schema)`**: tool calling guarantees that the output matches the schema, and you get a validated object directly
- Manual parsing (ask for JSON in the prompt, extract it, then validate with Zod) is the fallback when the model does not support tool calling
- For manual parsing, use a `SystemMessage` to tell the model to return JSON, and set `temperature` to 0 for more deterministic output
- Zod handles validation and type safety (see Chapter 11)
- In an agent, you can pass `responseFormat` to `createAgent` (the result is in `structuredResponse`)
