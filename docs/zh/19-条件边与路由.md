## 🤔 为什么需要条件边？

普通边的路线是**写死**的：

```javascript
.addEdge("A", "B")  // A 之后永远是 B
```

但真实 Agent 需要按**当前状态**做决定：

```
              ┌─ 需要查资料？─→ [调用工具] ─┐
[模型思考] ───┤                            │
              └─ 不需要 ──→ [直接回答] ←── 循环回来
```

"要不要调工具"是运行时才知道的事——这就是**条件边**的用武之地。

---

## 📦 addConditionalEdges 基本用法

```javascript
graph.addConditionalEdges(sourceNode, routerFunction);
```

- `sourceNode`：从哪个节点出发
- `routerFunction`：路由函数，接收当前状态，**返回下一个节点的名字**（或 `END`）

### 路由函数的规则

```javascript
const router = (state) => {
  if (/* 条件 1 */) return "nodeA";   // 返回节点名
  if (/* 条件 2 */) return ["b1", "b2"]; // 也可以返回数组 = 并行走多条路
  return END;                          // 或结束图
};
```

## 💡 完整示例 1：意图路由客服

根据用户问题里的关键词，路由到不同处理节点（无 LLM 也能跑，先跑通结构）。

> 💡 **要点：** 条件边挂在"从某个节点出发"的位置上。想在**入口处**就分流，标准做法是：`START` 先指向一个中转节点，在这个节点后面接条件边。

创建 `intent-router.js`：

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  question: Annotation,   // 用户问题
  answer: Annotation,     // 回答
});

// 路由函数：读状态，返回下一步节点名
function routeIntent(state) {
  const q = state.question;
  if (q.includes("退款") || q.includes("订单")) return "billing";
  if (q.includes("报错") || q.includes("bug")) return "technical";
  return "general";
}

const graph = new StateGraph(StateAnnotation)
  .addNode("billing", (state) => ({
    answer: `[订单客服] 已收到您的问题：「${state.question}」，将为您处理退款。`,
  }))
  .addNode("technical", (state) => ({
    answer: `[技术支持] 关于「${state.question}」，请先重启再清缓存试试。`,
  }))
  .addNode("general", (state) => ({
    answer: `[人工客服] 您的问题已记录，稍后专人回复。`,
  }))
  .addEdge(START, "router")           // 入口先到 router
  .addNode("router", (state) => ({})) // router 节点本身不更新状态，只做中转
  .addConditionalEdges("router", routeIntent)  // router 之后按状态分流
  .addEdge("billing", END)
  .addEdge("technical", END)
  .addEdge("general", END)
  .compile();

// 测试
console.log((await graph.invoke({ question: "我想退款" })).answer);
// [订单客服] 已收到您的问题：「我想退款」，将为您处理退款。

console.log((await graph.invoke({ question: "页面报错了" })).answer);
// [技术支持] 关于「页面报错了」，请先重启再清缓存试试。

console.log((await graph.invoke({ question: "你好呀" })).answer);
// [人工客服] 您的问题已记录，稍后专人回复。
```

## 🔀 用 LLM 做路由判断

把关键词匹配换成 LLM 判断，就是常见的"语义路由"：

```javascript
async function routeIntent(state) {
  const res = await model.invoke(
    `判断用户问题的类别，只返回一个词（billing/technical/general）：\n${state.question}`
  );
  const category = res.content.trim();
  return ["billing", "technical", "general"].includes(category)
    ? category
    : "general";  // 兜底：模型输出不靠谱时走默认分支
}
```

> 💡 **提示：** 路由函数可以写成 `async`。但注意：路由判断越快越好，能不调 LLM 就别调（省时间省钱），简单规则能解决的就先走规则。

## 🗺️ pathMap：路由结果映射

路由函数也可以返回任意 key，通过第三个参数映射到真正的节点名：

```javascript
.addConditionalEdges(
  "check",
  (state) => (state.ok ? "yes" : "no"),   // 返回 key
  { yes: "goodNode", no: "badNode" }      // key → 节点名 的映射表
)
```

> 💡 **说明：** 直接返回节点名（示例 1 的写法）最直观，入门推荐。pathMap 适合"路由函数不想知道具体节点名"的解耦场景。

## 📤 Send：动态分发（Map-Reduce 模式）

条件边每次只能"选一条路"，但如果你想**一次派出 N 个并行任务**呢？比如：

> "给 5 个主题各写一个笑话" → 派出 5 个并行的"写笑话"节点，每个拿到的输入还不一样！

这就是 `Send` 的能力：**在路由函数里返回若干个 `Send` 对象，每个 `Send` 指定一个目标节点和它的专属输入**。

```javascript
import { Send } from "@langchain/langgraph";

function dispatchJobs(state) {
  // 为每个主题生成一个 Send：Send(目标节点名, 该次执行的输入)
  return state.topics.map((topic) => new Send("writeJoke", { topic }));
}

graph.addConditionalEdges("generateTopics", dispatchJobs);
```

### 完整示例

创建 `map-reduce.js`：

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { Annotation, StateGraph, START, END, Send } from "@langchain/langgraph";

const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

const StateAnnotation = Annotation.Root({
  topics: Annotation,           // 主题列表
  jokes: Annotation({           // 收集所有笑话 → 必须配 reducer
    reducer: (existing, update) => existing.concat(update),
    default: () => [],
  }),
});

// 节点 1：生成主题（也可以是写死的列表）
async function generateTopics(state) {
  const res = await model.invoke("给我 3 个适合讲笑话的主题，用顿号分隔，只返回主题。");
  return { topics: res.content.split("、").map((t) => t.trim()) };
}

// 节点 2：写笑话（会被并行执行多次，每次收到不同的 topic）
async function writeJoke(input) {
  // 注意：Send 的第二个参数就是这个节点的输入（不再是整张图的状态）
  const res = await model.invoke(`用主题「${input.topic}」写一个 50 字笑话。`);
  return { jokes: [res.content] };
}

// 路由：把主题列表派发成 N 个并行任务
function dispatchJobs(state) {
  return state.topics.map((topic) => new Send("writeJoke", { topic }));
}

const graph = new StateGraph(StateAnnotation)
  .addNode("generateTopics", generateTopics)
  .addNode("writeJoke", writeJoke)
  .addEdge(START, "generateTopics")
  .addConditionalEdges("generateTopics", dispatchJobs)
  .addEdge("writeJoke", END)
  .compile();

const result = await graph.invoke({});
console.log(`生成了 ${result.jokes.length} 个笑话：`);
result.jokes.forEach((j, i) => console.log(`${i + 1}. ${j}`));
```

要点：

```
generateTopics 返回 { topics: ["猫", "上班", "外卖"] }
        │
        ▼ dispatchJobs 派发
   ┌─ Send(writeJoke, {topic:"猫"}) ───→ writeJoke ─┐
   ├─ Send(writeJoke, {topic:"上班"}) ──→ writeJoke ─┼─→ 各自结束后到 END
   └─ Send(writeJoke, {topic:"外卖"}) ──→ writeJoke ─┘
                          （三个并行执行，jokes 靠 reducer 收集）
```

> ⚠️ **注意：** `Send` 派发的节点，其函数参数是 **Send 的第二个参数**（本次任务的专属输入），不是图的全局状态。收集结果依然要用带 reducer 的字段。

## 🔁 递归上限 recursionLimit

图可以循环，但循环次数要有上限。LangGraph 默认最多执行 **25** 个超级步，超了会抛 `GraphRecursionError`：

```javascript
import { GraphRecursionError } from "@langchain/langgraph";

try {
  await graph.invoke(input, { recursionLimit: 50 });  // 提高上限
} catch (e) {
  if (e instanceof GraphRecursionError) {
    console.log("超过执行步数上限");
  }
}
```

> 💡 **说明：** 每经过一个节点算一步。Agent 型图（模型↔工具来回循环）步数增长快，循环较多时记得调大这个值。

## 🆚 条件边 vs Command 怎么选？

| 场景 | 推荐 |
|------|------|
| 根据状态选一条路，逻辑需要复用 | 条件边 + 路由函数 |
| 在节点执行过程中临时决定去向（结果决定去向） | 节点返回 `Command({ goto })` |
| 一次派生 N 个并行任务（每个输入不同） | `Send` |
| 固定路线 | 普通边 `addEdge` |

## ⚠️ 注意事项

### 1. 路由返回的节点名必须已注册

```javascript
// ❌ 路由返回 "billing" 但图里没有 addNode("billing", ...)
// 运行时报错：Node `billing` is unknown
```

### 2. END 用常量，别写死字符串

```javascript
return END;        // ✅ 推荐等价于 "__end__"
return "__end__";  // 能用但可读性差
```

### 3. 记得给 Send 目标节点配 reducer 字段收集结果

并行写入同一个字段而没有 reducer，会直接报错（第 17 章）。

### 4. 路由函数尽量保持"纯粹"

路由函数里不要做重活（如大文件读写），它每步都会执行；LLM 调用能省则省。

## 📝 本章小结

- `addConditionalEdges(source, router)`：router 读状态、返回下一步节点名或 `END`
- router 可以返回数组（多路并行），也可以配合 pathMap 做解耦映射
- `new Send(node, input)` 实现动态分发：一个路由派出 N 个并行任务，每个任务有专属输入
- 默认递归上限 25 步，用 `{ recursionLimit: N }` 调整
- 下一章我们会用「条件边 + 循环」亲手搭一个 ReAct Agent
