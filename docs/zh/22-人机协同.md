# 22-人机协同（Human-in-the-loop）

> 📅 适用于 LangGraph.js v1.x | 👶 零基础友好
> 💡 **注意：** 本章需要先学完第 21 章（Checkpointer），因为暂停/恢复依赖检查点

---

## 🎯 本章目标

- ✅ 理解 `interrupt`：让图暂停等人类介入
- ✅ 用 `Command({ resume })` 恢复执行
- ✅ 实现一个"执行前人工审批"的完整流程
- ✅ 记住使用 `interrupt` 的几条铁律

---

## 🤔 为什么需要人机协同？

Agent 越自主，风险越大。这些场景你一定不放心让 AI 全自动干：

- 💸 执行退款、下单、转账等敏感操作
- 📧 群发邮件、对外发布公告
- 🗑️ 删除数据、修改生产环境配置

**人机协同（Human-in-the-loop）** 的思路：图执行到关键节点时**暂停**，把信息抛给人类，等人类**批准/修改/拒绝**后再继续。

LangGraph 提供的机制就叫 **`interrupt`**（中断）。

---

## 📦 interrupt 的三要素

```javascript
import { interrupt, Command, MemorySaver } from "@langchain/langgraph";
```

| 要素 | 说明 |
|------|------|
| 1. **Checkpointer** | 暂停 = 保存现场，必须有检查点（第 21 章） |
| 2. **thread_id** | 恢复时靠它找回上次保存的状态 |
| 3. **interrupt() 调用** | 在节点里调用，图立即暂停，把值抛给调用方 |

工作原理：

```
节点执行到 interrupt(问题)
      │
      1️⃣ 图暂停，状态已存入检查点
      2️⃣ interrupt(问题) 的值抛给调用方（result.__interrupt__）
      │
      ……（人类思考、审批，图静静等待）……
      │
调用 graph.invoke(new Command({ resume: 人类的答复 }), config)
      │
      3️⃣ 节点从头重新执行
      4️⃣ interrupt() 这次不再暂停，而是返回 resume 的值
      │
      ▼
   节点继续往下跑
```

> ⚠️ **关键点：** 恢复时节点是**从头重新执行**的，`interrupt()` 的返回值就是 `Command({ resume })` 传入的值。

## 💡 完整示例：下单审批流程

模拟一个"AI 帮你下单，下单前必须人工确认"的流程。

创建 `approval-flow.js`：

```javascript
import {
  Annotation, StateGraph, START, END,
  MemorySaver, interrupt, Command,
} from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  item: Annotation,        // 要购买的商品
  price: Annotation,       // 价格
  approved: Annotation,    // 是否批准
  orderResult: Annotation, // 下单结果
});

// 节点 1：准备订单
function prepareOrder(state) {
  console.log("📦 准备订单:", state.item, "价格:", state.price);
  return {};
}

// 节点 2：人工审批 —— 核心节点！
function humanApproval(state) {
  // 暂停执行，把审批请求抛给外部
  // payload 必须是可 JSON 序列化的
  const decision = interrupt({
    question: "是否批准这笔订单？",
    item: state.item,
    price: state.price,
  });
  // 首次执行：走到这里就暂停了，下面的代码不执行
  // 恢复执行：decision 就是 Command({ resume: ... }) 传入的值

  console.log("👤 人工决定:", decision);
  return { approved: decision.approved };
}

// 节点 3：执行下单
function placeOrder(state) {
  console.log("✅ 订单已提交:", state.item);
  return { orderResult: `${state.item} 下单成功` };
}

// 节点 4：取消流程
function cancelOrder(state) {
  console.log("🚫 用户取消了订单");
  return { orderResult: "订单已取消" };
}

// 构建图
const graph = new StateGraph(StateAnnotation)
  .addNode("prepareOrder", prepareOrder)
  .addNode("humanApproval", humanApproval)
  .addNode("placeOrder", placeOrder)
  .addNode("cancelOrder", cancelOrder)
  .addEdge(START, "prepareOrder")
  .addEdge("prepareOrder", "humanApproval")
  // 审批后按结果分流
  .addConditionalEdges("humanApproval", (state) =>
    state.approved ? "placeOrder" : "cancelOrder"
  )
  .addEdge("placeOrder", END)
  .addEdge("cancelOrder", END)
  // 必须挂 checkpointer！
  .compile({ checkpointer: new MemorySaver() });

const config = { configurable: { thread_id: "order-1001" } };

// ===== 第一次调用：走到审批节点会暂停 =====
const result1 = await graph.invoke(
  { item: "机械键盘", price: 599 },
  config
);

// 检查暂停信息：result.__interrupt__ 数组
const interruptInfo = result1.__interrupt__[0];
console.log("\n⏸️ 图已暂停，等待人工审批:");
console.log(interruptInfo.value);
// { question: "是否批准这笔订单？", item: "机械键盘", price: 599 }

// ===== 人工审批（真实场景中这里可能过了几小时、甚至几天）=====

// 批准：用 Command({ resume }) 恢复执行
const result2 = await graph.invoke(
  new Command({ resume: { approved: true, reason: "价格合理，买！" } }),
  config
);

console.log("\n最终结果:", result2.orderResult);
// ✅ 订单已提交: 机械键盘
// 最终结果: 机械键盘 下单成功
```

如果人类想拒绝，把 resume 的值换掉即可：

```javascript
// 拒绝
await graph.invoke(
  new Command({ resume: { approved: false, reason: "太贵了" } }),
  config
);
// 图会走 cancelOrder 分支 → "订单已取消"
```

## 🔍 三个节点执行过程复盘

```
第一次 invoke:
  prepareOrder ✅ → humanApproval 执行到 interrupt() → ⏸️ 暂停
  返回值 result1.__interrupt__ 里带着审批请求

第二次 invoke（Command resume）:
  加载检查点 → humanApproval 从头重新执行
  → interrupt() 这次"秒过"，返回 { approved: true, ... }
  → 条件边分流 → placeOrder → END
```

> 💡 **说明：** `__interrupt__` 是一个数组——如果同一超级步有多个节点同时暂停，里面会有多个中断项，每个都有 `id`，恢复时可以分别给值。

## 🛠️ 在工具里使用 interrupt

第 20 章的 ReAct Agent 也能加人工审批——直接在**工具函数**里调用 `interrupt`，模型每次想用这个工具都会先暂停等人批准：

```javascript
import { tool } from "@langchain/core/tools";
import { interrupt, Command } from "@langchain/langgraph";
import { z } from "zod";

const sendEmailTool = tool(
  async ({ to, subject }) => {
    // 暂停，等人工审批
    const response = interrupt({
      action: "send_email",
      to,
      subject,
    });

    if (response?.approved) {
      return `邮件已发送给 ${to}，主题：${subject}`;
    }
    return "用户取消了发送";
  },
  {
    name: "send_email",
    description: "给指定邮箱发送邮件（发送前需要人工批准）",
    schema: z.object({
      to: z.string().describe("收件人邮箱"),
      subject: z.string().describe("邮件主题"),
    }),
  }
);
```

配合 `createReactAgent` 使用：

```javascript
const agent = createReactAgent({
  llm: model,
  tools: [sendEmailTool],
  checkpointSaver: new MemorySaver(),  // interrupt 必须有 checkpointer
});

// 第一次调用：模型决定发邮件 → 工具里 interrupt 暂停
let result = await agent.invoke(
  { messages: [new HumanMessage("给 boss@company.com 发一封请假邮件")] },
  { configurable: { thread_id: "email-1" } }
);
console.log(result.__interrupt__[0].value);
// { action: "send_email", to: "boss@company.com", subject: "..." }

// 人工批准后恢复
result = await agent.invoke(
  new Command({ resume: { approved: true } }),
  { configurable: { thread_id: "email-1" } }
);
```

## ⚠️ interrupt 的四条铁律

官方文档明确列出的规则，违反会得到诡异 bug：

### 1. 不要用 try/catch 包裹 interrupt()

```javascript
// ❌ 错误：interrupt 内部靠特殊错误实现暂停，catch 会破坏它
try {
  const answer = interrupt("问题");
} catch (e) { /* ... */ }

// ✅ 正确：interrupt 单独放在 try/catch 外面
const answer = interrupt("问题");
```

### 2. 不要在节点里移动 interrupt 的调用位置

恢复时节点从头重跑，如果两次执行的 `interrupt()` 顺序/数量不一致，resume 值会错位。**中断逻辑要写死、稳定。**

### 3. interrupt 的返回值要简单，resume 值要可 JSON 序列化

payload 和 resume 值都会被存进检查点，传字符串、数字、普通对象没问题；传函数、类实例会出问题。

### 4. interrupt 之前的副作用必须幂等

因为恢复时节点**从头重跑**，interrupt 之前的代码会再执行一遍：

```javascript
// ❌ 危险：恢复后 count 会被加两次
function badNode(state) {
  const total = state.count + 1;      // 会重复执行
  const ok = interrupt("确认继续？");  // 暂停点
  return { count: total };
}

// ✅ 安全：把副作用放到 interrupt 之后，或保证重复执行无副作用
function goodNode(state) {
  const ok = interrupt("确认继续？");  // 先暂停
  return { count: state.count + 1 };  // 批准后才执行
}
```

## 📝 本章小结

- `interrupt(payload)` 让图暂停并抛出问题；必须配合 **checkpointer + thread_id**
- 暂停信息在返回值的 `__interrupt__` 数组里
- 用 `new Command({ resume: 值 })` 作为输入再次 invoke 即可恢复；resume 的值就是 `interrupt()` 的返回值
- 恢复时节点**从头重跑** → interrupt 前的代码必须幂等
- interrupt 可以放在工具函数里，给 ReAct Agent 的敏感操作加审批
