# 21-记忆与持久化（Checkpointer）

> 📅 适用于 LangGraph.js v1.x | 👶 零基础友好
> 💡 **注意：** 需要 Node.js 18+。本章的 MemorySaver 是后续人机协同（第 22 章）的前提

---

## 🎯 本章目标

- ✅ 理解检查点（Checkpointer）机制
- ✅ 用 `MemorySaver` + `thread_id` 实现多轮对话记忆
- ✅ 用 `getState` 查看图状态
- ✅ 了解生产环境的持久化方案

---

## 🤔 为什么需要持久化？

回顾第 09 章：LangChain v1.x 里我们**手动维护消息数组**实现记忆。LangGraph 提供了更系统的方案——**检查点（Checkpointer）**：

```
每次图执行，LangGraph 在每个"超级步"边界自动保存状态快照（checkpoint）
                │
                ▼
快照按 thread（会话）组织，用 thread_id 区分不同对话
                │
                ▼
下次用同一个 thread_id 调用 → 自动加载上次的状态继续
```

持久化带来四大能力：

| 能力 | 说明 |
|------|------|
| **对话记忆** | 同一 thread 的多次调用共享状态（多轮对话） |
| **人机协同** | 图可以暂停，等人处理后再恢复（第 22 章） |
| **容错恢复** | 节点失败后从最近的检查点重跑 |
| **时间旅行** | 回看/回放历史执行过程（调试利器） |

---

## 📦 MemorySaver：内存检查点

`MemorySaver` 把检查点存在内存里，最适合学习和测试：

```javascript
import { MemorySaver } from "@langchain/langgraph";

const checkpointer = new MemorySaver();

// 编译时挂上 checkpointer
const graph = builder.compile({ checkpointer });
```

> ⚠️ **重要：** 挂了 checkpointer 之后，**每次调用图都必须提供 `thread_id`**，否则无法保存/恢复状态。

## 💡 完整示例：多轮对话记忆

创建 `memory-demo.js`（ReAct Agent 版）：

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { HumanMessage } from "@langchain/core/messages";
import { tool } from "@langchain/core/tools";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import { z } from "zod";

const model = new ChatOpenAI({
  model: "MiniMax/MiniMax-M2.5",
  apiKey: process.env.MODELSCOPE_API_KEY,
  configuration: {
    baseURL: "https://api-inference.modelscope.cn/v1",
  },
});

const timeTool = tool(
  async () => new Date().toLocaleString("zh-CN"),
  {
    name: "get_time",
    description: "获取当前日期和时间",
    schema: z.object({}),
  }
);

// 1. 创建检查点器
const checkpointer = new MemorySaver();

// 2. 创建 Agent 时挂载
const agent = createReactAgent({
  llm: model,
  tools: [timeTool],
  prompt: "你是一个友好的 AI 助手，记住用户告诉你的信息。",
  checkpointSaver: checkpointer,   // ← 关键参数
});

// 3. 每次调用都用同一个 thread_id
const config = { configurable: { thread_id: "conversation-1" } };

// 第一轮
let result = await agent.invoke(
  { messages: [new HumanMessage("我叫小明，今年 25 岁")] },
  config
);
console.log("AI:", result.messages[result.messages.length - 1].content);

// 第二轮：换了个全新的调用，但同一 thread
result = await agent.invoke(
  { messages: [new HumanMessage("我叫什么名字？今年多大？")] },
  config   // ← 同一个 thread_id
);
console.log("AI:", result.messages[result.messages.length - 1].content);
```

运行效果：

```
AI: 你好小明！很高兴认识你，我已经记住了。
AI: 你叫小明，今年 25 岁。
    ↑ 第二轮调用并没有传第一轮的消息，但 AI 记得！
```

### 记忆存在哪？

就存在**线程的状态**里。第二次 `invoke` 时，LangGraph 自动加载了 `conversation-1` 线程里保存的完整 `messages` 历史，新消息追加在后面——不再需要像第 09 章那样手动 push 消息数组。

> 💡 **换个 thread_id = 新会话。** 把 `thread_id` 换成 `"conversation-2"` 再问"我叫什么"，AI 就不记得了。客服系统里，每个用户会话分配一个 thread_id 就是这么简单。

## 🔍 getState：查看图状态

```javascript
const state = await agent.getState(config);

console.log(state.values);       // 当前完整状态 { messages: [...] }
console.log(state.next);         // 接下来要执行的节点（空数组 = 执行完毕）
console.log(state.metadata.step); // 执行到第几个超级步
```

### StateSnapshot 常用字段

| 字段 | 说明 |
|------|------|
| `values` | 该检查点时刻的完整状态 |
| `next` | 下一步要执行的节点名数组（`[]` 表示执行完毕） |
| `metadata` | 元信息：`step`（步数）、`writes`（哪个节点写了什么）、`source` |
| `createdAt` | 检查点创建时间 |
| `tasks` | 当前步的任务列表（含中断信息，第 22 章会用到） |

## 🕰️ getStateHistory：时间旅行

图执行的**每一步**都有检查点，可以完整回看：

```javascript
const config = { configurable: { thread_id: "conversation-1" } };

// 按时间从新到旧遍历所有检查点
for await (const snapshot of agent.getStateHistory(config)) {
  console.log(
    `step=${snapshot.metadata.step}`,
    `next=${snapshot.next}`,
    `messages数量=${snapshot.values.messages?.length}`
  );
}
```

输出示意：

```
step=3 next=[] messages数量=4          ← 最后一次执行完
step=2 next=[] messages数量=3
step=1 next=[] messages数量=2
step=0 next=['agent'] messages数量=1   ← 刚收到输入
```

这个能力在调试 Agent 时极其有用："它第 3 步到底收到了什么？"——翻检查点就知道。

### 手动改状态：updateState

```javascript
// 以某个节点的名义手动更新状态（会走该字段的 reducer）
await agent.updateState(config, {
  messages: [new HumanMessage("(人工补充：我最喜欢蓝色)")],
});
```

> 💡 **说明：** `updateState` 会创建一个**新的检查点**，不影响历史。配合人机协同（第 22 章）可以做"人工审核修改 Agent 状态"的流程。

## 💾 生产环境：持久化到数据库

`MemorySaver` 存在内存里，**进程重启就丢**。生产环境换用数据库实现的 Checkpointer，接口完全一样：

| 包 | 存储 | 安装 |
|----|------|------|
| `@langchain/langgraph-checkpoint-sqlite` | SQLite | `npm i @langchain/langgraph-checkpoint-sqlite` |
| `@langchain/langgraph-checkpoint-postgres` | PostgreSQL | `npm i @langchain/langgraph-checkpoint-postgres` |

```javascript
// 以 SQLite 为例（用法示意，具体以对应包文档为准）
import { SqliteSaver } from "@langchain/langgraph-checkpoint-sqlite";

const checkpointer = SqliteSaver.fromConnString("./memory.db");
const graph = builder.compile({ checkpointer });
```

> 💡 **说明：** 换 Checkpointer 只需要改一行，业务代码零改动——这就是接口抽象的好处。

## ✂️ 管理消息历史：防止 token 爆炸

对话越聊越长，token 消耗越来越大，还可能撑爆模型上下文窗口。两种常用应对方式：

### 做法 1：发给模型前手动裁剪（最简单）

状态里保留完整历史，但**发给模型时只取最近 N 条**：

```javascript
async function callModel(state) {
  // 只把最近 10 条消息发给模型，完整历史仍保存在状态里
  const recentMessages = state.messages.slice(-10);
  const response = await model.invoke(recentMessages);
  return { messages: [response] };
}
```

> 💡 **说明：** 裁剪只影响"发给模型的内容"，`state.messages` 本身不变。这是多轮 Agent 控制 token 最常用的手段。

### 做法 2：清空重来（REMOVE_ALL_MESSAGES）

官方提供了特殊标记 `REMOVE_ALL_MESSAGES`，把它和后续消息一起返回，会**先清空历史再追加**：

```javascript
import { REMOVE_ALL_MESSAGES } from "@langchain/langgraph";

// 清空对话历史，从这条新消息重新开始
return { messages: [REMOVE_ALL_MESSAGES, new HumanMessage("我们聊个新话题")] };
```

> 💡 **延伸：** 更多消息操作（按 id 删除指定消息、修剪中间的工具消息等）见官方文档 [add-memory](https://docs.langchain.com/oss/javascript/langgraph/add-memory)。

## ⚠️ 注意事项

### 1. 挂了 checkpointer 就必须给 thread_id

```javascript
// ❌ 报错：checkpointer 需要 thread_id
await graph.invoke(input);

// ✅ 正确
await graph.invoke(input, { configurable: { thread_id: "1" } });
```

### 2. MemorySaver 重启即失忆

内存存储仅适合本地开发调试。要跨进程/跨机器保存，用 SQLite/Postgres 版 Checkpointer。

### 3. 带 reducer 的字段 updateState 会"追加"

`messages` 字段的 reducer 是追加语义，`updateState` 写入的消息会**追加**到历史末尾，而不是覆盖。

### 4. 状态必须可序列化

检查点要落库，所以状态字段要能 JSON 序列化（第 17 章讲过的规则）。

---

## 📝 本章小结

- Checkpointer 在每个超级步自动保存状态快照，按 `thread_id` 组织
- `MemorySaver` 内存版：`compile({ checkpointer })` + 调用时传 `{ configurable: { thread_id } }`
- 同一 thread_id 的多次调用自动共享状态 → **多轮对话记忆**
- `getState` 看当前状态，`getStateHistory` 回放执行历史，`updateState` 手动改状态
- 生产环境换 SQLite/Postgres Checkpointer，接口不变
