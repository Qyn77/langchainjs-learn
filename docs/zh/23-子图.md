# 23-子图（Subgraphs）：图里套图

> 📅 适用于 LangGraph.js v1.x | 👶 零基础友好
> 💡 **注意：** 需要 Node.js 18+

---

## 🎯 本章目标

- ✅ 理解子图的用途：复用、分治、多 Agent 的基石
- ✅ 掌握两种集成方式：直接当节点 / 在节点内调用
- ✅ 了解子图的持久化（checkpointer）规则

---

## 🤔 什么是子图？

**子图 = 被当作"节点"使用的另一张图。**

```
父图:
START → [节点A] → [子图整体] → [节点B] → END
                       │
                       ▼
                  子图内部:
                  sub1 → sub2 → sub3
```

为什么需要它？

| 需求 | 子图的作用 |
|------|-----------|
| **复用** | 一套"搜索 + 总结"流程在多个图里都用 → 打包成子图 |
| **分治** | 大图太乱 → 按业务拆成几个小图，各写各的 |
| **团队协作** | 不同小组维护不同子图，只要约定好输入/输出 |
| **多 Agent** | 每个 Agent 就是一个子图（第 24 章的主角） |

---

## 🔀 两种集成方式（选哪种？）

| 方式 | 适用条件 | 写法 |
|------|---------|------|
| **方式一：直接当节点** | 父图和子图**共享状态字段**（比如都用 `MessagesAnnotation`） | `addNode("name", 编译后的子图)` |
| **方式二：在节点内调用** | 父图和子图**状态不同**，需要手动转换 | 节点函数里 `subgraph.invoke(...)` |

---

## 💡 方式一：共享状态，直接当节点

子图和父图用同一份状态定义，编译后的子图可以直接 `addNode`。

创建 `shared-state-subgraph.js`：

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

// ===== 共享的状态定义（父图子图都用它）=====
const StateAnnotation = Annotation.Root({
  text: Annotation,
  summary: Annotation,
});

// ===== 定义子图：搜索 + 提炼 =====
const subgraph = new StateGraph(StateAnnotation)
  .addNode("analyze", (state) => {
    console.log("  [子图] 分析文本:", state.text);
    return { summary: `《${state.text}》的核心观点是...` };
  })
  .addEdge(START, "analyze")
  .addEdge("analyze", END)
  .compile();

// ===== 父图：预处理 → 子图 → 输出 =====
const graph = new StateGraph(StateAnnotation)
  .addNode("clean", (state) => {
    console.log("[父图] 预处理文本");
    return { text: state.text.trim() };
  })
  // ★ 编译好的子图直接作为节点！
  .addNode("analyzeFlow", subgraph)
  .addNode("report", (state) => {
    console.log("[父图] 生成报告，基于:", state.summary);
    return {};
  })
  .addEdge(START, "clean")
  .addEdge("clean", "analyzeFlow")
  .addEdge("analyzeFlow", "report")
  .addEdge("report", END)
  .compile();

await graph.invoke({ text: "  LangGraph 让 Agent 编排变得简单  " });
```

运行效果：

```
[父图] 预处理文本
  [子图] 分析文本: LangGraph 让 Agent 编排变得简单
[父图] 生成报告，基于: 《LangGraph 让 Agent 编排变得简单》的核心观点是...
```

> 💡 **注意：** 子图里 `console.log` 的缩进可以看出执行顺序：父图节点 → 子图内部节点 → 父图节点，和普通节点完全一样地排进执行流。

子图还可以有自己的**私有字段**——子图的状态定义比父图多几个字段，多出来的部分父图看不见、也不受影响（父图状态里根本没有这些 key，子图内部自嗨）。

## 💡 方式二：不同状态，在节点内调用

父图和子图的状态字段完全不同时，写一个"翻译节点"做状态转换：

创建 `different-state-subgraph.js`：

```javascript
import { Annotation, StateGraph, START, END } from "@langchain/langgraph";

// ===== 子图状态：完全不同于父图 =====
const SubgraphState = Annotation.Root({
  keyword: Annotation,   // 子图只关心 keyword
  hits: Annotation({     // 子图自己的搜索结果
    reducer: (a, b) => a.concat(b),
    default: () => [],
  }),
});

const subgraph = new StateGraph(SubgraphState)
  .addNode("search", (state) => {
    console.log("  [子图] 搜索:", state.keyword);
    return { hits: [`${state.keyword}-结果1`, `${state.keyword}-结果2`] };
  })
  .addEdge(START, "search")
  .addEdge("search", END)
  .compile();

// ===== 父图状态 =====
const StateAnnotation = Annotation.Root({
  query: Annotation,     // 父图叫 query，子图叫 keyword——名字都对不上
  docs: Annotation({     // 父图叫 docs，子图叫 hits
    reducer: (a, b) => a.concat(b),
    default: () => [],
  }),
});

const graph = new StateGraph(StateAnnotation)
  .addNode("doSearch", async (state) => {
    // 1️⃣ 父图状态 → 子图状态（转换输入）
    const subResult = await subgraph.invoke({ keyword: state.query });
    // 2️⃣ 子图结果 → 父图状态（转换输出）
    return { docs: subResult.hits };
  })
  .addEdge(START, "doSearch")
  .addEdge("doSearch", END)
  .compile();

const result = await graph.invoke({ query: "LangGraph 教程" });
console.log(result.docs);
// [ 'LangGraph 教程-结果1', 'LangGraph 教程-结果2' ]
```

> 💡 **什么时候用方式二？** 最典型的场景：多 Agent 系统里每个 Agent 有自己的**私有消息历史**，只把最终回复同步给主对话。名字对不上、字段不对齐，全都靠节点函数手动转换。

## 💾 子图的持久化规则

子图的 checkpointer 有三种模式（在**编译子图时**设置）：

| 模式 | 编译写法 | 行为 |
|------|---------|------|
| **默认（推荐）** | `.compile()` | 不带自己的 checkpointer，每次调用从零开始，但**继承父图的 checkpointer**（子图里的 interrupt 也能正常暂停恢复） |
| **独立记忆** | `.compile({ checkpointer: new MemorySaver() })` | 子图状态跨调用保留——适合"子 Agent 需要多轮记忆"的场景 |
| **完全无状态** | `.compile({ checkpointer: false })` | 像普通函数一样跑，不支持 interrupt |

> ⚠️ **前提：** 父图自己必须挂了 checkpointer，子图的持久化和 interrupt 才生效。

```javascript
// 示例：子图独立记忆（跨多次父图调用保留自己的状态）
const subgraph = subgraphBuilder.compile({ checkpointer: new MemorySaver() });

// 父图调用两次，子图第二次能"记得"第一次
const parent = new StateGraph(StateAnnotation)
  .addNode("mySub", subgraph)
  ...
  .compile({ checkpointer: new MemorySaver() });
```

## 🔍 查看子图的执行细节

流式输出时加 `subgraphs: true`，就能看到子图内部每一步的更新（第 25 章详解流式）：

```javascript
const stream = await graph.stream(
  { query: "LangGraph 教程" },
  { subgraphs: true, streamMode: "updates" }
);

for await (const [namespace, update] of stream) {
  // namespace 为 [] 表示父图，非空表示子图内部
  console.log(`[${namespace.join("/") || "父图"}]`, JSON.stringify(update));
}
```

输出示意：

```
[父图] {"doSearch":{...}}            ← 父图节点
[doSearch:uuid] {"search":{...}}     ← 子图内部的节点
[doSearch:uuid] {"__end__":null}
[父图] {"__end__":{...}}
```

## ⚠️ 注意事项

### 1. 方式一要求子图先编译

```javascript
// ❌ 错误：addNode 传了未编译的构建器
.addNode("sub", subgraphBuilder)

// ✅ 正确：先 .compile() 再传入
.addNode("sub", subgraphBuilder.compile())
```

### 2. 共享字段要真的"同名同义"

方式一依赖状态字段名完全一致。父图叫 `docs` 子图叫 `hits`，就不共享了——要么统一命名，要么用方式二手动转换。

### 3. 子图不要和父图形成环

子图内部可以有循环，但父图 → 子图 → 父图的调用链要避免死循环（和普通循环一样受 `recursionLimit` 保护）。

### 4. interrupt 记得检查 checkpointer

子图里用 `interrupt` 的前提：父图挂了 checkpointer（默认模式自动继承）。

---

## 📝 本章小结

- 子图 = 被当作节点用的图，用于**复用、分治、多 Agent**
- 共享状态 → 编译后直接 `addNode("name", compiledSubgraph)`
- 状态不同 → 节点函数里 `subgraph.invoke()`，手动转换输入输出
- 子图默认继承父图 checkpointer；也可独立记忆或完全无状态
- `stream({ subgraphs: true })` 能看到子图内部每一步
